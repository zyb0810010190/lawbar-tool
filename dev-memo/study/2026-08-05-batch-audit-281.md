## Mistakes / near-misses (the load-bearing lesson)
- **Skipped re-running the gate after a "comment-only" edit.** During WI-2d audit remediation I fixed a header
  comment in `viewMatter.ts` (1 line → 2) and reasoned "comments are stripped by the scanner, no gate impact" — so
  I did NOT regenerate the allowlist or re-run the gate before committing `2275551`. **Wrong:** the i18n allowlist
  records literal LINE NUMBERS, and adding a comment line shifts every literal below it, breaking the drift +
  stale-entries guards. The batch audit caught it (attempt 1 comment, re-audit allowlist). **Rule going forward:
  re-run the full gate after ANY source edit — comments included — before committing.** A comment edit is not
  guaranteed gate-neutral when a line-indexed artifact (allowlist) is in play.
- **Override cascade.** The above turned one trivial fix into two audit-DUE-deadlock overrides. Reinforces the
  standing friction note: the strict "any finding = FAIL" batch protocol + audit-DUE guard deadlocks on trivial
  Lows during interactive feature-branch work. A WORKFLOW WI to let comment/allowlist-only fixes land without a
  human override (or a "deferred-Low → PASS" path) would remove this friction — flagged, not done.
