- **Palette kept, structure only.** The "rigid" feel came from flat hairline "cards", sharp 3px corners, and print
  ornaments — not the colours. So the restyle revalues radius/shadow (+ later serif/ornaments) and leaves every hue
  token untouched. *Falsifier:* if the warm palette itself later reads wrong against the new elevation, revisit —
  but that is a palette decision, out of this lane.
- **Font-order reversed to Noto-first (WI-1).** An initial "system-font-first" idea was reversed on discovering the
  live S1 offline-determinism policy + its guarding test (`smoke.electron.test.mjs:161`). Kept `--font-ui`
  Noto-first; serif-drop deferred to WI-2b. *Falsifier:* none pending — S1 stays green.
- **WI-1 narrowed to radius-only.** The WI-1 audit found the shadow tokens have zero consumers (revaluing them is
  visually inert) and the serif alias is an incoherent half-measure. So shadow + serif moved to the component layer
  (WI-2a wired shadows; WI-2b will drop serif properly). WI-1 shipped only the genuinely-consumed radius change.

## Mistakes / near-misses
- **cc-suite runner ENOBUFS (RUNNER_ERROR) — root-caused + fixed.** The batch-280 audit failed `spawnSync codex
  ENOBUFS` three times (high ×2, medium ×1) with empty rawOutput. Cause: the runner captures `codex exec` output
  with Node's **default 1MB `spawnSync` maxBuffer** (`runCodexSync`), and since `--quiet` was dropped for codex-cli
  ≥0.133 compatibility, `codex exec` streams verbose session output >1MB on a batch audit → overflow → ENOBUFS.
  Not a leak (0 orphaned processes), not prompt size (7.7KB failed). **Fix (Frank-authorized 2026-08-05, "go on"
  to the narrow `~/.claude` patch):** raised the runner's `spawnSync` `maxBuffer` to 64MB
  (`~/.claude/plugins/cache/xiaolai/cc-suite/0.2.18/scripts/codex-runner.mjs`; backed up to `*.bak-maxbuffer`).
  Buffer-only change; the re-run captured full output and passed. Logged to `dev-memo/cc-suite-reliability-log.md`.
  **Caveat:** the patch is in the plugin cache — a cc-suite version bump will drop it; re-apply if ENOBUFS recurs.
- **Path-2 MCP used for corroboration only.** The MCP audit confirmed the verdict but cannot feed the closeout
  (no runner job file); the sanctioned marker advance still required the patched runner's job.
