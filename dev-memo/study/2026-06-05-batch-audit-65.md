## Decisions (alternatives, why chosen, what would falsify)

1. **Neutralize-then-split rather than a full shell tokenizer** — the minimal correct fix is to blind the existing separator split to in-quote characters, not to re-implement shell parsing. Bounded handling keeps the change small and auditable. Falsifier: an under-count path where a genuine out-of-quote chain is collapsed to 1 (audit A2 + the verify probe found none across `&&`/`;`/`|`/`&`).
2. **Unbalanced-quote → fall back to original (over-deny)** — the only safe failure direction for a commit-boundary guard is over-deny; under-count is a security regression. Falsifier: an unbalanced-quote input that neutralizes a real separator without falling back (test "unbalanced quote + real && = 2" asserts DENY).
3. **Single-quote literalness (no backslash escape) vs double-quote escapes** — POSIX-correct so a real separator isn't wrongly neutralized. Audit A3 confirmed any mishandling trends toward over-count, not under-count.
