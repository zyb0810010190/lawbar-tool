## Redaction discipline (new, and it mattered)

The standing Layer-B pattern inlines `git diff BASE..HEAD` into the broker prompt. For this window that
diff's `-` lines contain **every identifier the commit removes** — inlining it verbatim would have
transmitted the client's name, docket numbers, court code, and counterparty to an external service,
undoing the remediation through the exact channel it closes. The diff was therefore redacted before
transmission and the outgoing file verified identifier-free.

**Round 1 (`audit-msleazf3-s7pm87`) returned BATCH-FAIL H1 — a self-inflicted artifact.** The redaction
was too broad: it also masked a generic 案由 (cause-of-action category). The auditor reasoned correctly
that a redacted token on a `+` line implies a real value survives the scrub — sound logic, wrong premise,
because the masked value was generic vocabulary identifying no one. The FAIL was NOT overridden; the
audit was re-run on a corrected input.

**Round 2 (this attestation) redacts TRUE identifiers only** — personal name, counterparty organization,
court code, docket numbers — leaving generic legal vocabulary intact, with an explicit scope note in the
prompt. H1 disappeared. **Lesson: redaction must be narrow. Over-redaction adds no safety and corrupts
the review signal.**
