## Decisions (alternatives / why / what would falsify)
- **Disclosure, not a top-level route (VS-3 §1).** Every sibling per-matter entity is a `<details>` in
  `viewMatter.ts`; a sidebar route would expand surface (router/nav/index) without added capability. Codex
  review-plan confirmed. *Falsifier:* if the register grows enough that a matter-scoped section becomes unusable,
  promote to a route + sidebar entry (paired with the edit slice).
- **Two truthful disabled states (VS-3 D3).** The design's single "add two parties" copy is inaccurate when a
  legacy matter already has parties but no backfilled ids; split into `<2 parties` vs `≥2 parties but <2
  id-bearing`. *Falsifier:* if a desktop party-id backfill action ships, the second state becomes an actionable
  affordance instead of a passive notice.
- **`sort_order` client auto-append (VS-3 D4).** v1 has no edit/reorder, so a create-time order control is half a
  feature; append preserves the lawyer's importance order. *Falsifier:* the manual-reorder slice (first VS-3
  follow-up) replaces append with an explicit order model.
- **`partyRoleLabel`, never fabricated 原告/被告 (VS-3 D8).** Per-party plaintiff/defendant is not modeled (the
  model has party.role client/opposing/third_party + a matter-level litigation_position). *Falsifier:* if a
  per-party litigation-role field is added, the suffix can use it.
