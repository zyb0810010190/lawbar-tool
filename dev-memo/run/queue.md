## WI-DPE2-FIX1: prototype-pollution hardening for assertValidDocketEntryEdit
Type: SOURCE
Scope: Close the post-merge Layer-B Medium (broker audit audit-mq9103q7-psj8cy, BATCH-FAIL C0 H0 M1 L0) AND the review-plan refinement (review-plan-mq91asr6-kr472n) on the just-merged assertValidDocketEntryEdit (docs/contracts/case-box-contract/src/docket-invariants.ts). Root cause: the helper advertises "own properties only", but BOTH its immutable check (isDeepStrictEqual(priorRec[key], revisedRec[key]) — bracket reads fall through the prototype) AND validateDocketEntry(revised) (ajv reads inherited + non-enumerable props) see a shape that differs from the JSON-persisted shape (which is own-ENUMERABLE only). Under Object.prototype pollution with a matching inherited field — OR an own NON-enumerable field — an attacker can delete an own key from `revised` and pass both checks while JSON.stringify(revised) omits a required field, persisting a self-inconsistent entry. This affects required IMMUTABLE fields (skipped-then-substituted) AND required EDITABLE fields (skipped by the immutable loop entirely, then substituted at validation): e.g. pollute Object.prototype.proposed_due_at, delete own revised.proposed_due_at — the immutable loop skips it (editable) and validateDocketEntry passes via the inherited value, yet JSON omits the required field (review-plan Medium). Fix (the reviewer's recommended approach — a MANUAL deep persisted-shape normalizer that uses ONLY intrinsics, never an attacker-reachable method lookup): JSON.stringify is unsafe as the sanitizer because it invokes toJSON via property lookup (review-plan High #1), AND `arr.map(...)` is unsafe because it looks up `.map` (own or polluted Array.prototype.map can synthesize the array — review-plan High #2). Capture intrinsics at module load (const objectKeys = Object.keys, arrayIsArray = Array.isArray, objectHasOwn = Object.hasOwn, numberIsFinite = Number.isFinite, objectCreate = Object.create, setHas = Set.prototype.has) so later reassignment of those globals / prototype pollution cannot subvert the normalizer. persistedShape(value): null → null; string/boolean → as-is; number → numberIsFinite(value) ? value : undefined; arrayIsArray(value) → build a fresh array with an INDEX LOOP (read len = value.length once; for i in 0..len-1: out[i] = objectHasOwn(value, i) ? persistedShape(value[i]) : null) — NO instance .map/.forEach/iterator; object → only if isPlainRecord(value) (proto is Object.prototype or null) build a NULL-PROTOTYPE record out = objectCreate(null) (so an own "__proto__" data key cannot trigger the legacy prototype setter — review-plan #2), take keys = objectKeys(value) (OWN ENUMERABLE only) and iterate it with an INDEX LOOP (NOT for...of, which would invoke the pollutable Array.prototype[Symbol.iterator] — review-plan #1), recursing each value and SKIPPING keys whose normalized value is undefined (a non-JSON optional value becomes absent, not an own undefined key — review-plan #4), else (class instance / Date / prototype-backed nested item) → undefined; function/symbol/bigint/undefined → undefined. The two top-level persistedShape calls are wrapped in try/catch (any throw → DocketEntryEditError; fail-safe, NOT a TOCTOU fix). This recursively reduces to own-enumerable JSON-primitive data at every level using ONLY captured intrinsics — ignoring toJSON, .map, the array iterator, the __proto__ setter, inherited, and non-enumerable properties — top-level AND nested reminder_offsets items alike. After the existing isPlainRecord(prior/revised) guard + the proposed-only check (both on the RAW inputs, so a non-proposed prior still throws IllegalTransitionError FIRST, identical ordering to today), compute priorOwn = persistedShape(prior), revisedOwn = persistedShape(revised); if either is not a plain record throw DocketEntryEditError. Then (b-immutable) iterate the union of objectKeys(priorOwn) and objectKeys(revisedOwn) with INDEX LOOPS (never for...of over the key arrays or a Set), test EDITABLE membership via the captured setHas.call(EDITABLE_DOCKET_ENTRY_FIELDS, key) (so a polluted Set.prototype.has cannot mark an immutable field editable — review-plan #4), and for every non-EDITABLE key require node:util.isDeepStrictEqual(priorOwn[key], revisedOwn[key]) (a key present on exactly one side outside EDITABLE is a DocketEntryEditError violation — subsumes add/remove-key); and (c-schema) call validateDocketEntry(revisedOwn) — validating the normalized persisted shape so an inherited (incl. toJSON), own-non-enumerable, polluted-iterator, or non-JSON value, at top level OR nested under the editable reminder_offsets, can never mask a missing required field.
