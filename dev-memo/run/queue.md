Mechanics: (a) ONE new read-only IPC channel `casebox:t3:previewCatalog` in the desktop main process — matter-scoped, tenant-injected; its request DTO + result type live in a NEW per-entity module `apps/lawbar-desktop/src/caseBox/dto/t3.ts` re-exported from the `dto.ts` barrel (mirrors dto/document.ts). The handler checks matter existence + active tenant BEFORE any evidence read, then DRAINS all `status:"accepted"` pages of `listEvidenceItems({ tenant_id, matter_id, status:"accepted", cursor })` (bounded page size, loop until `next_cursor === null` — S1 assigns 序号/order over the FULL input, so a single truncated page is FORBIDDEN), then calls the ALREADY-MERGED `buildT3CatalogModel` from `apps/lawbar-desktop/src/caseBox/export/t3CatalogModel.ts` ONCE (S1 is the single source of truth — NOT re-implemented). Result shape uses the EXISTING strict `IpcEnvelope` (`{ok:true,value}|{ok:false,error}`): a read error (unknown_matter/tenant_mismatch/invalid_payload) is `{ok:false,error}`; a submitter refusal is an EXPECTED review state carried in the SUCCESS value as a discriminated union `{kind:"model", model, modelSha256?} | {kind:"refusal", code}` (NEVER `null`), so a thrown `T3CatalogRefusal` is caught and mapped to `{ok:true,value:{kind:"refusal",code}}`, never a crash/error envelope; renderer never supplies `tenant_id`/`actor_user_id` (forbidden DTO fields → `invalid_payload`); absent matter → `unknown_matter` (evidence read not called); tenant mismatch → `tenant_mismatch`; (b) a NEW renderer sibling `renderer/screens/viewMatterT3Catalog.ts` rendering a read-only header (提交人诉讼地位 + 名称/姓名) + 4-column table (序号/证据名称/证明内容/页码) with the lazy-load `<details>` disclosure, `reviewNeeded` marker cells, empty state, error `role="alert"`, and refusal banner per the Design artifact's states table + data-test-ids; (c) minimal wiring into `renderer/screens/viewMatter.ts` to mount the section (extract mechanically to keep it under the loc-guardian warn threshold if needed, as prior siblings did); (d) the renderer read type mirroring `T3CatalogModel` as a renderer-side structural type in `renderer/types.ts` (NO contract-package change); (e) i18n strings via the existing allowlist; (f) targeted renderer + IPC tests + register any new test file in the desktop `package.json` test list. The surface renders the S1 model VERBATIM: ordering, `reviewNeeded` markers, non-promotion (证据名称/证明内容/页码 bind to evidence_title/proof_statement/exhibit_page_range ONLY — never notes/filename/party_side), default `accepted`-only status filter, submitter refuse-not-guess.
