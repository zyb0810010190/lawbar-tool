EditDocketEntryOpts carries the full SCOPE + actor + content (review-plan review-plan-mq9joana-myktjt High — a mutating op must express tenant/matter mismatch): tenant_id, matter_id, entry_id, editor_actor_user_id, and ONLY the six editable CONTENT fields (proposed_kind, proposed_due_at, proposed_due_at_kind, proposed_due_at_timezone, proposed_owner_user_id, reminder_offsets); it carries NO trusted revised_at. The full scope tuple mirrors GetDocketEntryQuery ({tenant_id,matter_id,entry_id}); NOTE (review-plan review-plan-mq9k05oz-xl4ug3): the existing ConfirmDocketEntryOpts/DismissDocketEntryOpts do NOT carry tenant_id/matter_id (src/types.ts:333) — editDocketEntry is DELIBERATELY MORE scoped than confirm/dismiss so a mutating op can assert+verify caller-claimed tenant/matter/entry isolation; a single scoped opts arg is used so entry_id rides the scope object (reviewer-preferred). Tenant/matter/entry checks run BEFORE any mutation and BEFORE audit emission. Error mapping (reuse existing errors.ts codes — NO new code unless review explicitly reopens it): unknown matter → unknown_matter; entry not in the requested matter → matter_id_mismatch; tenant mismatch → tenant_mismatch; unknown entry → throw CaseBoxPersistenceError("invalid_argument","unknown docket entry: …") — a mutating op THROWS, NEVER returns null (mirrors confirm/dismiss inMemoryDocket.ts:237,401); non-proposed prior (contract IllegalTransitionError) → re-thrown as illegal_transition (mirrors confirm inMemoryDocket.ts:270); DPE2 contract/provenance/revised-schema violation (DocketEntryEditError) → invalid_payload. Design: a pure prepareEditDocketEntry(prior, opts, ctx) in src/inMemoryDocket.ts returns { entry: revised, audit }: (1) proposed-only — a non-proposed prior fails via the contract invariant assertValidDocketEntryEdit throwing IllegalTransitionError(state,"proposed","edit") (ADR §2/§11); (2) build revised = prior with ONLY the six content fields replaced by the patch via an ALLOW-LIST apply (never a blind opts spread), then set revised.revised_at = ctx.nowIso() — SERVER-DERIVED; any caller-supplied revised_at is stripped/ignored and never persisted as trusted input (ADR §6; DPE2 Medium deferral). Sample the clock ONCE and reuse that single timestamp for BOTH payload_json.revised_at AND the DOCKET_ENTRY_REVISED.timestamp (no real-clock drift); (3) call the merged DPE2 contract invariant assertValidDocketEntryEdit(prior, revised) (content-only + provenance/identity/lifecycle immutable + revised-entry schema-valid) — persistence does NOT re-implement these; (4) build ONE DOCKET_ENTRY_REVISED audit event via buildCaseBoxAuditEvent (update/docket_entry/reasonRequired:false; before_state_hash=entityStateHash(prior), after_state_hash=entityStateHash(revised), prev_event_hash=prior chain head). Apply (in-memory, inMemoryDocket.ts + inMemoryRepo.ts): tenant/matter isolation (unknown_matter / tenant_mismatch; unknown entry per the get-precedent), atomically patch the entry in entriesByMatter + docketById and push the one audit event. Apply (SQLite, docketRepoQueries.ts + SqliteCaseBoxPersistence.ts): inside db.transaction().immediate() — load prior payload_json, requireMatterTenant, run a NEW DEDICATED edit-specific UPDATE helper (e.g. updateDocketEntryEditRow) that atomically patches the lifted proposed_kind column AND payload_json (confirmation_state stays proposed), then insertAuditEvent + upsertAuditChainHead for the one event. DECISION (user-directed): prefer a NEW edit-specific UPDATE helper over extending the generic updateDocketEntryRow — edit must update payload_json + lifted proposed_kind together; this is invariant-specific and must NOT broaden the generic helper the confirm/dismiss paths rely on (which patches only confirmation_state/confirmed_deadline_id/payload_json). NO schema migration: revised_at rides payload_json only (no column/index); schema.ts is FORBIDDEN — if a reviewer proves a lifted/indexed column is genuinely needed, STOP and split a separately-governed migration WI.
