## WI-A07-KEY-00: A0.7 marker/key custody operating model (design-only; NOT A0.7-gated)
Type: PLAN
A0.7-classification: A07-KEY-00 is design-only and intentionally NOT A0.7-gated. This docs-only ADR defines the OPERATING MODEL for HMAC-key custody; it executes no marker write/validation, mints no marker, exposes no key, and changes no gate behavior, so it needs no live provenance-valid A0.7 marker. Therefore this WI carries NO `Requires-A07:` line. The A0.7 hard gate (check-a07-gate.sh), the marker writer (a07-marker-write.sh / a07_marker.py write), the marker validator (a07_marker.py validate), and the marker schema are ALL left UNCHANGED by this lane. review-plan must confirm this classification; if review-plan says this docs-only WI must be A0.7-gated, STOP and report.
Scope: Author the A0.7 marker/key custody OPERATING MODEL as an ADR. Define: (1) how a human/developer supplies or withholds the A0.7 HMAC key (`LAWBAR_A07_MARKER_HMAC_KEY`) for local gated implementation WIs; (2) WHEN a marker may be minted; (3) WHO runs marker write + validation; (4) HOW an agent session may verify A0.7-dependent work without silently weakening the hard gate; (5) the accepted custody modes and the explicitly rejected modes; (6) the A3-T2 (and all A3 implementation WI) preconditions. Preserve the local-only marker/key policy. Design/ADR ONLY — no code (unless review-plan explicitly recommends a tiny documentation-integrity/cross-reference check OUTSIDE apps/native/.claude/.github), no key material, no marker generation, no gate/schema/writer/validator behavior change. Output: docs/adr/ADR-evidence-a07-key-custody-operating-model.md (A07-KEY-00); an optional narrow cross-reference note in the A3 ADR/plan only if review-plan recommends it.
Required decisions to record: (1) the HMAC key must NEVER be committed; (2) `LAWBAR_A07_MARKER_HMAC_KEY` remains local/env-only; (3) a marker is valid ONLY when generated by the existing marker writer AND validated by the existing validator; (4) if an agent cannot access the key, it MUST NOT claim A0.7-gated verification passed; (5) A3 implementation WIs with `Requires-A07: yes` MUST stop before commit if the key/marker is unavailable; (6) human-run marker minting ALONE is insufficient unless the validation environment ALSO has the key (validation needs the key in the same env that runs check-gates); (7) for now, do NOT switch from HMAC to asymmetric signing without a separate ADR/WI; (8) future CI validation requires a SEPARATE secret-management decision and MUST NOT be smuggled into A3; (9) accepted modes — (a) human exports the key to the local agent shell for the duration of ONE gated WI, (b) human runs BOTH marker mint and validation/check-gates directly, (c) the lane STOPS with verification pending if neither is acceptable; (10) rejected modes — throwaway agent-created key, committed key, committed marker as a substitute for validation, bypassing `Requires-A07`, weakening check-a07-gate.
