## WI-802: Tenant-scoped fact transition IPC (review / accept / reject)
Type: IMPL
Scope: add a tenant-scoped write IPC channel CHANNEL.factTransition ("casebox:fact:transition") + transitionFactHandler in factHandlers.ts that moves a fact through the already-implemented lifecycle via persistence.transitionFact (the contract status enum candidate|reviewed|accepted|rejected and the persistence transitionFact + getFact already exist — DO NOT rewrite the contract or persistence). Renderer-supplied DTO is narrow: { matterId, factId, to, rejection_reason? } where to in reviewed|accepted|rejected and rejection_reason is required + non-empty when to === "rejected" AND MUST be absent otherwise (rejection_reason supplied when to !== "rejected" -> invalid_payload; not silently dropped). The handler captures activeTenantId, the active actor user id, and the at timestamp ONCE per invocation and reuses them for getMatter / getFact / transitionFact (no repeated getter/clock calls). The server INJECTS reviewer_actor_user_id (active actor) + at (server clock); the renderer MUST NOT supply reviewer_actor_user_id, at, status, reviewed_at, accepted_at, rejected_at, supersedes_fact_id, source_type, id, tenant_id, actor_user_id (forbidden-field + unknown-field guards reject them -> invalid_payload). CRITICAL fail-closed scoping: persistence.transitionFact(factId, opts) is UNSCOPED (takes only factId, no tenant/matter), so the handler MUST first verify the fact belongs to the requested matter AND active tenant via a scoped getFact({tenant_id, matter_id, fact_id}) preflight and reject a null (unknown / wrong-matter / wrong-tenant) with invalid_payload BEFORE calling transitionFact — exactly the WI-601 docket-confirm preflight pattern — otherwise a guessed foreign factId could be transitioned cross-matter/cross-tenant. Flow: shape-guard -> forbidden-field -> unknown-field -> field validation (matterId, factId, to enum, rejection_reason-required-when-rejected) -> getMatter existence + active-tenant (unknown_matter / tenant_mismatch) -> scoped getFact preflight (invalid_payload on miss) -> persistence.transitionFact(factId, { to, reviewer_actor_user_id, at, ...(to==="rejected" ? { rejection_reason } : {}) }) -> project the returned fact through a dedicated renderer-safe allowlist (same non-authority fields as CREATE_FACT_RESPONSE_FIELDS, stripping tenant_id/actor_user_id/reviewer_actor_user_id) -> { ok:true, value }. The domain transition rules (which from-states allow which to) stay in persistence; the handler MUST NOT re-implement them and surfaces illegal_transition unchanged via mapThrownError. Register the channel in caseBoxHandlers.ts and wire it like the other write channels. Do NOT touch any renderer path; do NOT add the tests to the 1534-LOC tests/ipc-handlers.unit.test.mjs (use a NEW dedicated file).
