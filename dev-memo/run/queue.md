Scope: Implement a deterministic, idempotent, headless link-status resolver in the case-box-persistence package that realizes the A3-RESOLVE-00 status ladder (broken > needs_review > valid; valid NEVER a default) over the merged V9-V11 schema + case_box_documents. The resolver READS case_box_links, case_box_anchors, case_box_document_pages (V9), case_box_document_page_geometries (V10), case_box_documents; it WRITES ONLY case_box_links.status (a row is written only when the computed status differs from the stored one — no spurious writes). NO schema change, NO migration, NO export behavior, NO UI/product behavior, NO anchor-delete/cascade policy, NO dependency, NO marker/key/gate change. Document-replacement handling is scoped per the Option 1 reconciliation below.
Required decisions to record: (1) RESOLVER INPUTS — the 4 A3 tables (case_box_links, case_box_anchors, case_box_document_pages V9, case_box_document_page_geometries V10) + case_box_documents (read for the supersession reverse-lookup signal only; see decision 4). All bindings are app-layer invariants (no SQLite FKs). (2) BROKEN (ladder rung 1, highest precedence) — a link resolves to broken if the anchor target is missing (link.anchor_id has no case_box_anchors row), OR the page identity is missing (no case_box_document_pages row for the anchor's (document_id, physical_page_index)), OR the geometry record is missing (no case_box_document_page_geometries row for that page), OR the anchor is otherwise structurally un-resolvable (orphan / out-of-range). (3) NEEDS_REVIEW (rung 2) — else needs_review on geometry-version mismatch (anchor.geometry_captured_at != the current V10 case_box_document_page_geometries.captured_at for that page; INV-A3-6, no stale coordinate stays valid) OR on document supersession (decision 4). (4) DOCUMENT-REPLACEMENT RECONCILIATION (Option 1, user-authorized 2026-06-24) — the persisted case_box_documents.status enum is the OCR/triage pipeline (registered|ocr_pending|ocr_complete|ocr_failed|triaged|tagged|reviewed) and contains NONE of the Evidence DocumentStatus lifecycle values (canonical|replaced_pending_review|superseded). Therefore this WI detects document replacement ONLY from the persisted signal that exists today: a document D is considered superseded/replaced iff another case_box_documents row has supersedes_document_id == D.id (reverse lookup). Links whose anchor's document_id is a superseded document become needs_review. The resolver MUST NOT key Evidence canonical/replaced/superseded lifecycle off case_box_documents.status, and MUST NOT infer Evidence replacement from OCR/triage statuses (registered/ocr_pending/ocr_complete/ocr_failed/triaged/tagged/reviewed). The full Evidence document lifecycle (canonical -> replaced_pending_review -> superseded; A1-T7 replacement quarantine) is DEFERRED to a future A1-T7 / document-lifecycle SCHEMA WI. This is a deliberate, recorded reconciliation, not a silent deviation. (5) VALID (rung 3, lowest; NEVER a default) — a link is valid only if: the anchor exists, its page identity exists, its geometry record exists, anchor.geometry_captured_at == the current V10 captured_at for that page, AND the anchor's document is not superseded by the reverse-lookup signal. Source-identity resolution (the ADR's "source uncertainty" sub-condition over source_type/source_id) is OUT OF SCOPE for this WI and DEFERRED (only evidence has a persistence table today; note/question/calcTerm/claimElement have no M0 persistence) — flag to review-plan; if review-plan requires source-identity resolution now, STOP and report. (6) DETERMINISM + IDEMPOTENCE — the same inputs always yield the same status via the ladder; re-running on unchanged inputs produces no status change and no spurious writes/audit churn (write only when computed != stored). (7) AUDIT-EVENT DECISION — A3-RESOLVE-00 §7 deferred the audit-event shape as non-inferable. This WI is STATUS-ONLY: it writes case_box_links.status and emits NO audit event (no audit shape invented); the audit-event emission is recorded as a future decision/WI. If review-plan requires audit events now, STOP and report (do not invent a shape). (8) TRANSACTION BOUNDARY — the resolver updates affected links atomically per document/matter scope (one BEGIN/COMMIT per unit of work, mirroring existing case-box Mode-B atomicity), unless review-plan recommends a narrower per-link/per-page boundary. No partial-update state observable. (9) NO CASCADE — the resolver creates/deletes NO links or anchors and resolves NO anchor-delete/cascade policy (still UNRESOLVED; future stop-and-ask WI). (10) ENTRY POINT — a headless resolver entry point following existing package conventions (a src/sqlite resolver module, optionally re-exported from src/index.ts), callable with a db handle + tenant/matter (or document) scope; no network, no production-evidence ingestion, no encryption/key management.
