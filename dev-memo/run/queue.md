## WI-DPE5: UI — docket proposal edit affordance (renderer edit form + "(edited)" badge + renderer bridge)
Type: UI
Design artifact: dev-memo/design/2026-06-12-docket-proposal-edit-ui.md (DPE5 UI direction; design commit 56e19b4c9329fb01187e959e9eb482eccbd27dae)
Scope: Add the renderer UI to edit a PROPOSED docket entry's content, the terminal layer of the docket-proposal-edit feature (contract DPE2 → hardening FIX1 → persistence DPE3 → IPC/DTO DPE4 → UI DPE5). Renderer-only: NO persistence/IPC/contract/error-map change, NO new IPC channel (the DPE4 casebox:docket:edit channel + preload method are reused verbatim). Per-row two-step reveal mirroring the existing in-row Dismiss control (apps/lawbar-desktop/renderer/screens/viewMatterDocketProposals.ts): Edit button → inline form prefilled with the current editable content → Save changes / Cancel; Dismiss is hidden while editing; Edit and Confirm stay DISTINCT actions (NO edit-then-confirm shortcut per ADR §3 — a saved edit keeps the entry proposed). DPE5 OWNS the renderer bridge for the DPE4 preload method: add editDocketEntry to the CaseBoxClient + CaseBoxApi interfaces and the createCaseBoxApi impl (stripDtoFields(dto, RENDERER_EDIT_DOCKET_DTO_FIELDS)) in renderer/api.ts; add the renderer EditDocketEntryDto mirror (8 fields) + RENDERER_EDIT_DOCKET_DTO_FIELDS allowlist to renderer/types.ts. Form scope: FIVE editable scalar controls (proposed_kind, proposed_due_at, proposed_due_at_kind {datetime|date_only}, proposed_due_at_timezone {host zone; null only with date_only}, proposed_owner_user_id) + reminder_offsets PASSTHROUGH/READ-ONLY (display existing reminders read-only; send the unchanged existing value on save; NO rich reminder editor in DPE5 — deferred to a separate future WI). Forbidden from the form: NO editable control for tenant/matter-authority/actor (tenant_id, matter_id authority, actor_user_id, editor_actor_user_id), identity (id/entry_id), provenance (source_type, source_rule_citation, extractor_*, extraction_confidence, source_document_id, source_page_number, source_excerpt), lifecycle/audit (confirmation_state, proposed_at, confirmation_actor_user_id, confirmed_at, confirmed_deadline_id, dismissal_actor_user_id, dismissed_at, dismissal_reason, created_at), or revised_at; revised_at is DISPLAY-ONLY edited-state metadata. matterId/entryId are immutable scope the screen already holds (not user-editable fields). Edited state: render an "(edited)" badge (accessible text, not color-only) on a row whose projected revised_at is present; any timestamp shown is secondary/non-authoritative. Save calls api.editDocketEntry({matterId, entryId, + the six content fields}) — success keeps the entry proposed and refreshes/reconciles the row IN PLACE (existing generation-guarded refresh) with new values + the badge; error keeps the form open, shows the normalized inline alert (env.error.message, static no-leak from main) via role="alert", re-enables Save, does NOT refresh; Cancel exits edit mode with NO API call. Re-entrancy guard prevents a double Save firing two edits. confirm/dismiss/create/list behavior + pagination + the loadGen generation guard are unchanged. LOC: if the edit control pushes viewMatterDocketProposals.ts toward the 800 pure-LOC source cap, extract a mechanical sibling apps/lawbar-desktop/renderer/screens/viewMatterDocketProposalEdit.ts (same shape as the dismiss control) — pre-authorized to avoid a mid-WI stop. The sibling, if split, owns ONLY the form DOM, field validation, and the save/cancel callbacks; viewMatterDocketProposals.ts RETAINS row/list lifecycle, pagination, the loadGen generation guard, and refresh ownership (review-036 Low #2).
Source of truth: docs/adr/docket-proposal-edit.md §3 (six editable fields; no edit-then-confirm), §4 (immutable provenance/lifecycle), §6 (revised_at → "(edited)" badge; machine-suggested vs user-edited), §9 (DPE5 = UI); dev-memo/design/2026-06-12-docket-proposal-edit-ui.md (the committed UI direction); dev-memo/plan-batch-casebox-docket-proposal-edit-ui-00.md (the plan); the merged DPE4 surface (apps/lawbar-desktop/src/caseBox/dto/docket.ts EditDocketEntryDto/EDIT_DOCKET_DTO_FIELDS/DOCKET_ENTRY_RESPONSE_FIELDS incl. revised_at/EditDocketEntryResult; electron/preload.mts CaseBoxApi.editDocketEntry + casebox:docket:edit); the existing renderer patterns — viewMatterDocketProposals.ts (the dismiss two-step reveal + pagination + loadGen guard), viewMatterDeadlines.ts (the add-deadline two-step input + host-zone findUniqueInstant resolver), renderer/api.ts (stripDtoFields + createCaseBoxApi + the confirm/dismiss bridges), renderer/types.ts (DTO mirrors + RENDERER_*_DOCKET_DTO_FIELDS + the existing CONFIRM/DISMISS allowlists), dom.ts (el/setText), format.ts (formatLocalDateTime); the test harness tests/_view-matter-dom.mjs (MockDoc + makeStubApi) + the existing renderer-deadline-write.test.mjs / renderer-dto-sync.test.mjs / renderer-api.test.mjs.

Acceptance criteria: Edit reveals a form prefilled with the five editable values + the read-only reminders and HIDES Dismiss while editing; Save sends EXACTLY {matterId, entryId, proposed_kind, proposed_due_at, proposed_due_at_kind, proposed_due_at_timezone, proposed_owner_user_id, reminder_offsets} with NO authority/provenance/lifecycle/revised_at field and reminder_offsets equal to the unchanged existing value PASSED AS DATA (the projected row value, NOT a UI-serialized string) — asserted for BOTH the null case and the non-empty array case (review-036 Low #1; test asserts the DTO passed to api.editDocketEntry); RENDERER_EDIT_DOCKET_DTO_FIELDS equals exactly the 8 DTO fields and stripDtoFields drops any other key (test); a successful Save keeps the entry proposed and the row refreshes IN PLACE showing the new values + an "(edited)" badge; the "(edited)" badge renders when revised_at is present and is ABSENT when revised_at is missing; an IPC error keeps the form open, displays the normalized inline alert via role="alert", re-enables Save, does NOT refresh, and contains no tenant/matter/id; Cancel makes NO api call; client validation blocks an empty proposed_kind / invalid date with NO api call; Edit/Save/Cancel are keyboard reachable and focus returns predictably (Escape cancels); confirm/dismiss/create/list behavior is unchanged; the apps test suite passes; loc-guardian PASS; the committed diff touches ONLY the declared allowed files; broker audit returns no Critical/High/Medium and verify confirms ALL CLOSED.
