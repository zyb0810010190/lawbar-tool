Specify the deterministic rules by which anchors/links resolve to LinkStatus valid|needs_review|broken (mismatch / replacement / missing-target), grounded in the merged V9-V11 schema + the existing case_box_documents replacement fields. Design/ADR ONLY — no code, no schema/migration change, no UI, no export behavior, no anchor-delete cascade resolution, no dependency, no marker/key/gate change. Required decisions to record: (1) resolver INPUTS — case_box_anchors, case_box_links, case_box_document_pages (V9), case_box_document_page_geometries (V10), and the document replacement/supersession fields already present in case_box_documents (status, supersedes_document_id); (2) VALID condition — an anchor is valid only if its document/page identity exists (a V9 case_box_document_pages row for (document_id, physical_page_index)) AND its geometry provenance matches the current expected geometry for that page (anchor.geometry_captured_at == the current V10 case_box_document_page_geometries.captured_at for the same page); a link is valid only if its anchor target resolves to a valid anchor AND its required source identity (source_type, source_id) still resolves; (3) GEOMETRY MISMATCH — if anchor.geometry_captured_at does not match the current page geometry provenance, the affected link status becomes needs_review; no stale coordinate remains silently valid (INV-A3-6); (4) DOCUMENT REPLACEMENT/QUARANTINE — replacement/supersession of the underlying document (case_box_documents.status leaving canonical / supersedes_document_id chain) moves affected links to needs_review; any quarantine/withdrawn/unavailable document state represented in the existing status field must not remain silently valid; (5) MISSING TARGET — a missing page identity, missing geometry record, or missing anchor target becomes explicit broken; (6) STATUS WRITES — the resolver may set valid|needs_review|broken; it NEVER defaults to valid; status changes are deterministic and idempotent (re-running the resolver on unchanged inputs yields the same statuses, no spurious writes/audit churn); (7) AUDITABILITY — decide whether resolver status changes write audit events in the first implementation WI or defer to a later WI; if the audit-event shape is unclear, DEFER and record it as a future WI (do not invent an audit shape here); (8) TRANSACTION BOUNDARY — the resolver should update affected links atomically per document/matter scope, unless review-plan recommends narrower; (9) NO CASCADE — do NOT resolve the anchor-delete cascade policy here; record that deleting anchors remains a future stop-and-ask WI (A3-SCHEMA-00 decision 5 / A3-CONTRACT-00 decision 9, still unresolved); (10) A0.7 GATING — this design-only WI is NOT A0.7-gated; the future resolver implementation WI MUST declare Requires-A07: yes (custody 9b).
