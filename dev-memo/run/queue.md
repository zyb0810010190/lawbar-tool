## WI-A3-UNLINK-T1: audited durable unlink/relink operation over case_box_links (A0.7-gated, custody 9b)
Type: IMPL
Requires-A07: yes
A0.7-classification: WI-A3-UNLINK-T1 implements the durable unlink/relink OPERATION that mutates court-facing evidence link state (the V12 `unlinked_at`/`unlink_reason` marker columns) and drives the resolver (`resolveLinkStatuses` -> `broken`) + export (`buildExportCitations` -> `UNLINKED`) presentation of legal-record link status. It changes legal-record presentation + unlink semantics, so it is A0.7-gated (the same A3 evidence-link surface WI-A3-UNLINK-RESOLVE / WI-A3-T5-RESOLVE / WI-A3-EXPORT-T1 gated under custody 9b). It carries `Requires-A07: yes` and runs under A07-KEY-00 custody mode 9b: the human mints the local marker + runs the A0.7-gated `check-gates.sh` with the HMAC key; the agent never receives the key; the implementation commit is blocked until the human reports gated PASS. If review-plan says this WI must NOT be A0.7-gated, STOP and report.
Scope: Implement the minimal, audited durable unlink/relink OPERATION over existing `case_box_links` rows, the emitter the merged predecessors (V12 marker columns; resolver/export marker-awareness; the LINK_UNLINKED/LINK_RELINKED audit kinds, PR #136) were built to support. Add two methods to the CONCRETE `SqliteCaseBoxPersistence` class: `unlinkLink(linkId, { actor_user_id, unlink_reason })` sets `unlinked_at = nowIso()` + `unlink_reason`; `relinkLink(linkId, { actor_user_id })` clears both marker columns to NULL. Each operation appends EXACTLY ONE tamper-evident v2 audit chain event in the SAME `BEGIN IMMEDIATE` transaction as the row UPDATE: `LINK_UNLINKED` (action update, entity_type link, reasonRequired true) on unlink, `LINK_RELINKED` (action update, entity_type link, reasonRequired false) on relink — built via `buildCaseBoxAuditEvent` with correct before/after/prev state hashes, mirroring `applyTransitionDeadlineSqlite`. SQLite-only (links are an A3 SQLite-only feature; `InMemoryCaseBoxPersistence` has NO link support, so the methods go on the concrete class, NOT the shared `CaseBoxPersistence` interface — InMemory untouched). The marker write + audit append are atomic: no marker mutation without a chain event, no chain event without a marker mutation. The link row is PRESERVED (UPDATE only, never DELETE).
Required decisions to record: (1) SURFACE — two public methods on the CONCRETE `SqliteCaseBoxPersistence` only (not the shared interface), each `#runImmediateWrite((db, deps) => apply{Unlink,Relink}LinkSqlite(...))`, backed by a new `linkRepoQueries.ts` (`loadLinkForUpdate`, `prepareUnlinkLink`, `prepareRelinkLink`, `updateLinkMarkerRow`, `apply*Sqlite`, `linkStateForHash`) mirroring `deadlineRepoQueries.ts`. If review-plan prefers standalone `(db, …, deps)` exports like the other A3 read functions, record/STOP. (2) STATE HASH — `before_state_hash`/`after_state_hash` over `linkStateForHash(row)` = the authoritative persisted identity + marker fields (id, tenant_id, matter_id, source_type, source_id, anchor_id, created_at, payload_json, unlinked_at, unlink_reason), EXCLUDING the resolver-derived `status` (non-authoritative), via `entityStateHash`. If review-plan wants the full row hashed, record. (3) RE-UNLINK / RE-RELINK — deterministically REJECTED with `illegal_transition` (unlink on a row with `unlinked_at` NOT NULL; relink on a row with `unlinked_at` NULL); not an idempotent no-op (a second event would drop/duplicate the audit record). (4) TIMESTAMP — capture a SINGLE `const stamp = deps.nowIso()` ONCE per operation and use the SAME `stamp` for BOTH `unlinked_at` AND the audit event `timestamp` (do NOT call `deps.nowIso()` twice — the injected test clock advances per call, so two calls diverge; the marker and its event must be forensically identical). A test MUST assert the LINK_UNLINKED event's `timestamp` equals the row's `unlinked_at`. `makeClock` gives determinism. (review Medium, 2026-06-26.) (5) RELINK REASON — relink takes NO reason; clears `unlink_reason` to NULL; the LINK_RELINKED event omits `reason` (matches reasonRequired false). (6) REASON VALIDATION — `unlink_reason` validated non-empty/non-blank at the operation boundary (guaranteeing "row unchanged" before any write) -> `invalid_argument`; the contract builder's `reasonRequired` is the second guard. (7) NOT-FOUND — a missing `linkId` -> `invalid_argument` (no event). (8) MARKER-ONLY UPDATE — the UPDATE sets `unlinked_at` + `unlink_reason` ONLY; never `status` (resolver-owned), never `payload_json`, never a DELETE. (9) INTEGRATION (read-through, no behavior change) — after unlink, `resolveLinkStatuses` resolves `broken` + `buildExportCitations` flags `UNLINKED`; after relink, the resolver recomputes from the lower rungs (a structurally-broken link still resolves `broken`). (10) A0.7 — A0.7-gated, custody 9b (Requires-A07: yes).
