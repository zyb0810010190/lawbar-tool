## WI-A3-CASCADE-00: anchor-delete policy design (design-only; NOT A0.7-gated)
Type: PLAN
A0.7-classification: A3-CASCADE-00 is design-only and intentionally NOT A0.7-gated. This docs-only ADR/plan RESOLVES the long-deferred anchor-delete/cascade policy (how anchor deletion behaves relative to case_box_links + the resolver/export) BEFORE any delete behavior is implemented; it implements no delete code, no schema/migration, no UI, and changes no gate/marker behavior, so it needs no live provenance-valid A0.7 marker. Therefore this WI carries NO `Requires-A07:` line. ANY FUTURE implementation that changes delete/link semantics MUST declare `Requires-A07: yes` (custody mode 9b). review-plan must confirm this classification; if review-plan says this docs-only WI must be A0.7-gated, STOP and report.
Scope: Resolve the anchor-delete cascade policy as an ADR + a dev-memo sequencing plan, BEFORE any delete behavior is implemented, preserving citation trust + auditability and preventing silent destruction of evidence links. Specify the deterministic policy by which anchor deletion behaves relative to case_box_links, the resolver (resolveLinkStatuses), and the export builder (buildExportCitations) — grounded in the merged V9-V11 schema + the case-box no-FK convention. Design/ADR ONLY — no code, no schema/migration change, no resolver/export behavior change, no UI, no delete implementation, no soft-delete/tombstone columns, no dependency, no marker/key/gate change. Output: docs/adr/ADR-evidence-a3-anchor-delete-policy.md (A3-CASCADE-00) + dev-memo/plan-batch-casebox-evidence-a3-cascade-policy-00.md; an optional additive cross-reference to the A3 schema/resolver/export ADRs only if review-plan recommends it.
Default policy direction (record + justify in the ADR): do NOT physically delete an anchor that is referenced by any case_box_links row; referenced-anchor deletion is rejected/blocked by application behavior (no SQLite ON DELETE CASCADE; no silent physical cascade; no silent link deletion; no automatic clean export from a deleted/missing anchor). A future explicit unlink/break-link workflow may be designed separately but MUST NOT be an implicit cascade. The existing resolver missing-anchor -> broken behavior remains a SAFETY NET for corrupted/manual/inconsistent state, NOT the normal deletion workflow and NOT permission to cascade-delete anchors.
Required decisions to record (the 8 ADR questions): (1) REFERENCED-ANCHOR DELETE — preferred: REJECT deletion if any case_box_links row references the anchor (anchor_id); record WHY this is safer for legal evidence integrity (a referenced anchor is load-bearing for a citation; deleting it would either orphan links or force a silent cascade, both of which destroy or degrade evidence trust). (2) UNREFERENCED-ANCHOR DELETE — define whether a physical delete is allowed when NO links reference the anchor; if uncertain, DEFER and require an explicit product decision (record as a future decision, do not guess). (3) LINK DELETE / UNLINK — decide whether unlink is separate from anchor delete; recommended: unlink/break-link is a SEPARATE future WI, NOT part of anchor delete (an explicit, audited workflow), never an implicit cascade. (4) BROKEN SAFETY NET — the resolver missing-anchor -> broken behavior (A3-RESOLVE-00) remains valid for inconsistent/corrupted data; it MUST NOT be treated as permission to cascade-delete anchors or as the normal deletion path. (5) EXPORT BEHAVIOR — a missing anchor MUST continue exporting a deterministic BROKEN object (A3-EXPORT-00 / buildExportCitations A10 no-drop), never a silent omission and never a clean citation. (6) AUDIT — decide whether anchor-delete rejection / unlink / delete emit audit events now or DEFER; if the audit-event shape is unclear, DEFER and record it as a future WI (do not invent an audit shape here). (7) SCHEMA — do NOT add FK / ON DELETE CASCADE; do NOT add soft-delete/tombstone columns in this design lane; if soft-delete is later desired, record it as a future schema WI (not decided here). (8) A0.7 — this design-only WI is NOT A0.7-gated; ANY future implementation changing delete/link semantics MUST declare Requires-A07: yes (custody 9b).
