## WI-FORMS-T3-S1-LOGICAL-EXPORT-ADAPTER-00: T3 证据目录及说明 deterministic logical export model (Type: IMPL)
Type: IMPL
Scope: Implement ONLY the T3 证据目录及说明 renderer-independent logical export model/adapter (parent plan `dev-memo/plan-forms-t3-evidence-catalog-00.md` §4 slice S1; ADR `dev-memo/adr-forms-t3-s0-schema.md` §6, BINDING). A NEW pure apps-layer module `apps/lawbar-desktop/src/caseBox/export/t3CatalogModel.ts` that consumes ALREADY-MERGED S0 payload fields (`evidence_title`, `proof_statement`, `display_order`, matter `litigation_position`, existing `exhibit_page_range`) and produces a deterministic `T3CatalogModel`. Design (mirrors the A10-T6 pattern in `a10CanonicalExportModel.ts` — DUPLICATES the small module-private `nfc`/`stableStringify`/`sha256` helpers LOCALLY per ADR §6; does NOT import, extend, or modify `a10CanonicalExportModel.ts`): (a) input is a pure function `buildT3CatalogModel({ matter, evidenceItems, submitterSelection?, includeStatuses? })` over LOCAL structural type-only input interfaces (no new runtime dependency, no contract-package import); (b) output `T3CatalogModel` = `{ formType: "证据目录及说明" (constant), matterId, litigationPosition (header cell), submitterName, rows[] }`; each row = `{ sequence (序号 1..n), evidenceId, evidenceName (证据名称), proofStatement (证明内容), pageRange (页码) }`; (c) every visible cell is a discriminated union `{ text: string } XOR { reviewNeeded: true }` (A10 key-presence pattern) — a missing/blank `evidence_title`/`proof_statement`/`exhibit_page_range` renders `{ reviewNeeded: true }`, NEVER a fabricated or substituted value; litigationPosition cell is `{ value: "plaintiff"|"defendant" }` from `matter.litigation_position` XOR `{ reviewNeeded: true }` when absent; (d) 证据名称 derives from `evidence_title` ONLY, 证明内容 from `proof_statement` ONLY, 页码 from `exhibit_page_range` ONLY — `notes`, `source_document_id`/document filename, `party_side`, and any other generic field are NEVER promoted into T3 display truth; (e) ordering rule: filter to `includeStatuses` (default `["accepted"]`, which excludes proposed/rejected/superseded so a supersession chain shows only the live row), then sort by (has-valid-`display_order` first, then `display_order` ASC, then `created_at` ASC, then `id` ASC); `display_order` is "valid" only when a non-negative integer (`Number.isInteger && >= 0`), otherwise treated as absent for ordering (rows without valid order sort AFTER ordered rows); ties fall to `created_at ASC, id ASC`; 序号 is the 1..n index over the ordered+filtered rows (raw `display_order` values are NOT exposed); (f) submitter selection: the submitter is the single `role === "client"` party (auto-selected → `submitterName = display_name`); if the matter has ZERO or >1 client parties the model REFUSES by throwing a typed `T3CatalogRefusal` (code `submitter_selection_required`) UNLESS an explicit `submitterSelection = { partyIndex, displayNameEcho }` is supplied that resolves to a `client` party whose NFC `display_name` still equals the echo — a stale echo throws `submitter_selection_stale`, a non-client index throws `submitter_not_client` (mirrors the A1 ambiguous-citation refuse-not-guess posture); the matter-level `litigation_position` applies to ALL client parties (single matter-level field; no per-party position data exists in M0, so no per-party divergence path is invented — that would be a follow-up ADR); (g) determinism: `serializeT3CatalogModel(model)` (local recursive key-sorted, NFC-normalized, compact JSON — multi-clause Chinese proof text preserved verbatim, NFC only) + `t3CatalogModelSha256(model)` (sha256 of the serialization); a golden test pins byte-stable serialization + sha256; (h) 卷X页Y / A10 citation metadata is DELIBERATELY NOT attached in S1 (it would require the `DocumentPage`/A10 citation pipeline = scope expansion) — 页码 is always `exhibit_page_range` passthrough and no citation field exists to replace it (DR-00 Q4 preserved). Register the new golden test `apps/lawbar-desktop/tests/t3-catalog-model.unit.test.mjs` in the desktop `package.json` `test` script (the ONLY package.json edit — one entry appended to the `node --test ...` list; NO dependency/version/other-script change).
