Type: WORKFLOW

## WI-G2: Make batch commit-count parsing quote-aware (no over-deny on separators in -m messages)
Type: WORKFLOW
Scope: Close BCG-9 (Medium). `count_git_commits()` in `.claude/hooks/batch-commit-guard.sh` (line ~58) splits statements with a GLOBAL `awk` gsub over `&&|\|\||[;|&]` that is blind to shell quoting, so a separator inside a quoted `-m` message is treated as a statement boundary: `git commit -m "revert; git commit was wrong"` splits, the second fragment's command word resolves to `git`+`commit`, `NCOMMIT=2`, and the guard DENIES a legitimate SINGLE commit (line 96). It fails closed (over-denies, not a bypass) but is real friction. Fix: before splitting on separators, NEUTRALIZE quoted spans (single- and double-quoted, honoring backslash-escapes) so separators and command-like text INSIDE a quoted message are not treated as boundaries or command words; then split + count exactly as today. Preserve deny behavior for genuinely chained commands (`git commit ... && git commit ...` must still count 2). If quote-neutralization cannot be applied safely (e.g. unbalanced quotes), fall back to the CURRENT global-split behavior (which over-denies, never under-denies) to keep the fail-closed posture. Bounded quote handling only — NOT a general shell parser. WORKFLOW/SCAFFOLD only.
