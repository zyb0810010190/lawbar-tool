## Locked decisions (approved 2026-07-13; #11–#12 added 2026-07-14 from review-plan)

1. **Party identity** — add **optional `id: ULID`** to the party definition in **both** places it is declared: the standalone `case-box-party.schema.json` **and** `CaseBoxMatter.$defs.party`. Add an audited `ensureMatterPartyIds` matter-update path that backfills ids for existing id-less parties (schema support in WI-PTA-03; persistence helper in WI-PTA-08; IPC exposure + ClaimTrack reject-unknown-party validation in WI-PTA-12). ClaimTrack references `claimant_party_id`/`respondent_party_id` as ULIDs, and create/update **rejects** any value not present in the matter's `parties[]`. **No** array-index / display-name / denormalized-label refs.
2. **`submitted_by_side`** — `EvidencePreparation.submitted_by_side` nullable; authoritative **when explicitly set** (and may intentionally differ from `party_side`). When unset/null, the default is a **read-time projection** from `CaseBoxEvidenceItem.party_side` (`our→our_side`, `opposing→opposing_side`, `null/absent→unknown`) — **never written back** into `payload_json`. Does not duplicate/replace `party_side`.
3. **Audit-chain participation** — the four models participate in the tamper-evident chain. Additive `entity_type`/`event_kind` expansion accepted. **Every mutation emits an audit event** per existing `auditChain.ts` invariants.
4. **Evidence number/label** — no exhibit-number column on the existing evidence model. Label = `evidence_title`; any ordinal badge derived from existing ordering fields.
5. **ClaimTrack deletion** — guarded **hard-delete** + normal soft lifecycle (`status = withdrawn | resolved`). Hard-delete **blocked** when any EvidencePreparation / CrossExaminationOpinion / LegalOpinionCard references the track.
6. **`key_page`** — nullable integer `key_page` + nullable string `key_page_note`. No DocumentPage FK / anchor / bounding-box.
7. **Contract home** — the four models live in `case-box-contract`.
8. **Anchor/link reuse** — plain `evidence_id` references for this feature (coarse evidence-level linking), **not** the anchor/link engine. Revisit only if a later WI introduces anchor-level citation.
9. **WI granularity** — fine-grained WI-PTA-01 … WI-PTA-17 (**17 total, 16 after WI-PTA-01**); do not merge adjacent WIs.
10. **Placeholder** — line-964 placeholder removed on promotion (this file).
11. **Hard-delete audit action (review D-A)** — add an additive **`delete-hard`** action to the audit-event `action` enum, semantically **distinct** from `delete-soft`. ClaimTrack guarded hard-delete emits `action:delete-hard`. Update the audit vocabulary, `audit-log.ts` mapping, exhaustive `labels.ts`, and tests.
12. **LegalOpinionCard evidence-ref junction (review D-B)** — add `case_box_legal_opinion_card_evidence_refs` as part of **v14**, maintained **atomically** with LegalOpinionCard writes (no FK; `payload_json` remains canonical). Provides the indexed lookup for `listOpinionCardsReferencingEvidence(matter_id, evidence_id)`, avoiding a JSON scan.

## Architecture assessment (repo-grounded, condensed)

**Vocabulary owner** `docs/contracts/case-box-contract/`: JSON Schema draft 2020-12 → generated TS → Ajv validators; 11 ULID-keyed entities, each with `tenant_id`+`actor_user_id`; semantic invariants in TS helpers; conformance harness with explicit per-fixture valid/invalid tests + a stray-fixture sweep.

**Existing evidence field set** (`CaseBoxEvidenceItem`): `id, tenant_id, actor_user_id, matter_id, source_document_id?, exhibit_page_range?, lawyer_weight, status, supersedes_evidence_id?, notes?, evidence_title?, proof_statement?, display_order?, created_at, party_side?("our"|"opposing"|null)`. → **submitted-side partially exists** as `party_side` (2-valued); **no** exhibit number (only sort-only `display_order`); **no** opinion/cross-exam/claim fields. Party is **embedded in `Matter.parties[]`, id-less** (drives decision #1).

**Persistence** (`services/case-box-persistence/`): `CURRENT_SCHEMA_VERSION = 12`; strictly-additive frozen `DDL_STATEMENTS_V{N}`; **no FKs** (app-layer invariants); `payload_json` canonical + lifted columns for indexing; per-entity `*RepoQueries.ts`; every write inside caller `#runImmediateWrite` (BEGIN IMMEDIATE); seek-only cursor pagination; audit chain `event_count==COUNT==MAX(sequence)` per matter, updated atomically; `data-migration-compat.test.mjs` proves v1→vN opens without loss.

**IPC** (`apps/lawbar-desktop/`): `CHANNEL` registry → `ipcMain.handle` → per-entity `*Handlers.ts` with fixed chain (shape → forbidden-field → unknown-field → type/enum → **preflight matter+tenant fail-closed** → persistence → `projectRow` authority-strip → `mapThrownError` safe-message); preload bridge + renderer `api.ts` DTO-strip. **Renderer:** vanilla TS + `dom.ts el()`, hash router, `mount<Screen>` modules; existing evidence/doc surfaces are disclosure sub-panels in `viewMatter.ts`. **i18n:** zh-CN `catalog.ts` + `t()` + `labels.ts` facades; a **drift-guard test fails CI on any hardcoded literal** not in catalog/allowlist.

No conflicts remain unresolved after decisions #1–#12; all are additive and consistent with these patterns.

## Additive schema/contract diff

Strictly additive. Four new schemas + validators + generated types + fixtures; two additive migrations (v13, v14); additive `entity_type`/`event_kind` enum expansion; **one** optional field (`Party.id`) on an existing schema. No existing table altered; existing matters open with zero prep rows; `data-migration-compat` extends to v14.

**Standard fields on every new entity:** `id: ULID, tenant_id, actor_user_id, matter_id, created_at`; mutable entities add `updated_at`. All mutations emit audit events (decision #3).

### ClaimTrack — `case-box-claim-track.schema.json`
`track_type: main_claim|counterclaim` · `our_role: asserting|responding` · `claimant_party_id: ULID` · `respondent_party_id: ULID` · `title` (req) · `claim_summary?` · `response_summary?` · `legal_basis?` · `calculation_summary?` · `status: active|withdrawn|resolved` · `sort_order: int`. **No** schema max-one-counterclaim (test #4). **Referential rule:** `claimant_party_id`/`respondent_party_id` must be ids present in the matter's `parties[]` (handler-validated, WI-PTA-12; decision #1).

### EvidencePreparation — `case-box-evidence-preparation.schema.json`
`claim_track_id: ULID` · `evidence_id: ULID` (by-value ref) · `submitted_by_side: our_side|opposing_side|third_party|court_obtained|unknown | null` (decision #2 — authoritative when set; when null, **read-time projection** from `party_side`, never written back) · `evidence_purpose?` · `facts_to_prove: string[]` (short strings, item `maxLength`; test #7) · `trial_use_summary?` · `key_page: int|null` · `key_page_note: string|null` · `review_status: draft|in_review|confirmed` · `sort_order: int`. **DB UNIQUE `(claim_track_id, evidence_id)`** (test #6).

### CrossExaminationOpinion — `case-box-cross-examination-opinion.schema.json`
`claim_track_id: ULID` · `evidence_id: ULID` · `direction: our_objection_to_their_evidence|their_anticipated_objection_to_our_evidence` · `{authenticity,legality,relevance,probative_force}_status: admitted|denied|conditional|reserved|not_applicable` + matching `_reason?` · `overall_opinion?` · `courtroom_short_version?` · `our_response_short_version: string|null` (**semantic invariant: required iff `direction=their_anticipated_objection_to_our_evidence`**; test #11) · `preparation_status: draft|review_needed|ready_for_trial`. **DB UNIQUE `(claim_track_id, evidence_id, direction)`** (test #12). No `rebuttal_evidence_ids`.

### LegalOpinionCard — `case-box-legal-opinion-card.schema.json`
`claim_track_id: ULID|null` (null = matter-level) · `stage: claim_basis|claim_calculation|evidence_presentation|cross_examination|fact_finding|debate|final_statement|any` · `trigger_type: judge_question|opposing_argument|evidence_objection|disputed_point|planned_statement|procedural_issue|other` · `trigger_text: string|null` · `title` (req) · `full_opinion_text?` · `courtroom_short_version?` · `supporting_evidence_ids: ULID[]` (ordered) · `opposing_evidence_ids: ULID[]` (ordered) · `preparation_status: draft|review_needed|ready_for_trial` · `used_in_trial_at: ts|null` · `follow_up_flagged_at: ts|null` · `priority: int` · `sort_order: int`.

### Existing-contract additive changes
- `case-box-audit-event.schema.json`: `action += {delete-hard}` (decision #11, distinct from `delete-soft`); `entity_type += {claim_track, evidence_preparation, cross_examination_opinion, legal_opinion_card}`; `event_kind (v2) += {CLAIM_TRACK_CREATED,_UPDATED,_WITHDRAWN,_RESOLVED,_DELETED; EVIDENCE_PREPARATION_CREATED,_UPDATED,_DELETED; CROSS_EXAM_OPINION_CREATED,_UPDATED,_DELETED; LEGAL_OPINION_CARD_CREATED,_UPDATED,_DELETED,_USED_IN_TRIAL_SET,_USED_IN_TRIAL_CLEARED,_FOLLOW_UP_SET,_FOLLOW_UP_CLEARED}`. `CLAIM_TRACK_DELETED` carries `action:delete-hard`.
- Party `id`: optional `id: ULID` added to **both** `case-box-party.schema.json` **and** `case-box-matter.schema.json` `$defs.party` (decision #1). An audited `ensureMatterPartyIds` path backfills existing id-less parties (persistence WI-PTA-08, IPC WI-PTA-12).

### Persistence migrations
- **v13** — `case_box_claim_tracks`, `case_box_evidence_preparations` (+ list indices + UNIQUE `(claim_track_id, evidence_id)`).
- **v14** — `case_box_cross_examination_opinions` (+ UNIQUE `(claim_track_id, evidence_id, direction)`), `case_box_legal_opinion_cards` (+ lifted filter columns `stage, trigger_type, claim_track_id, preparation_status, used_in_trial_at, follow_up_flagged_at, priority, sort_order` + indices), and `case_box_legal_opinion_card_evidence_refs` (junction: `matter_id, card_id, evidence_id, ref_kind(supporting|opposing), position` + index on `(matter_id, evidence_id)`; maintained **atomically** with card writes — decision #12). No FKs; `payload_json` canonical; atomic audit write.

Brownfield matters need `ensureMatterPartyIds` before ClaimTrack creation. 5. Existing matters open unaffected (no altered table).
