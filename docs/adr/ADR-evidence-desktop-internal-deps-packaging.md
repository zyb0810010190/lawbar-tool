## 1. Context

`apps/lawbar-desktop` consumes two internal packages — `case-box-contract` and `case-box-persistence` — as **`file:dist-tarballs/*.tgz`** dependencies (the "tarball-install" architecture decided in `plan-desktop-package-architecture-00.md` rev-3, Option 2). The tarballs are **gitignored** (`apps/lawbar-desktop/.gitignore` → `dist-tarballs/`) and regenerated by `npm run bootstrap` → `pack:internal` (`scripts/pack-internal-packages.mjs` → `npm pack`). The committed **`apps/lawbar-desktop/package-lock.json` pins each tarball's sha512 integrity** (tarball-PoC plan §7.3: "the lockfile is committed").

## 2. The defect (evidence-grounded)

The D1 round-trip attempt (`WI-A3-LINK-D1-ROUNDTRIP-T1`) packaged the desktop app and exercised the real `casebox:link:create` IPC. It failed: `persistence.createLink` builds a `LINK_CREATED` audit event, but the **bundled** `case-box-contract` rejected it — `audit-event builder rejected LINK_CREATED: /kind unknown audit event kind "LINK_CREATED"` → `invalid_payload`.

Root cause, proven by clearing the npm cache and reinstalling:

```
npm error EINTEGRITY: wanted sha512-XFMRa8b…==  (apps/lawbar-desktop/package-lock.json pin)
                       but got sha512-9O4iETK…==  (current case-box-contract-0.1.0.tgz, 68870 bytes)
```

- The committed **lock pins `sha512-XFMRa8b…`** — an OLD `case-box-contract` tarball built **before** the `LINK_CREATED`/`LINK_UNLINKED`/`LINK_RELINKED` audit kinds were added (grep of that content → **0** LINK_* kinds).
- The **current** tarball, regenerated from the correct source (which **has** all 3 kinds → `dist-tarballs/manifest.json` records `sha512-9O4iETK…`), has a **different** integrity.
- `npm pack` is **not byte-reproducible** (it embeds file mtimes), so every repack yields a new integrity. The committed lock therefore goes stale the moment the gitignored tarballs are regenerated after any contract/persistence source change — exactly what happened when the contract gained the LINK_* kinds.

**Consequences (a real committed-repo defect, not a local-only quirk):**
- `npm ci` from the committed lock **fails `EINTEGRITY`** against a freshly-packed tarball; a plain `npm install` **silently keeps stale cached (=0) content**.
- A clean/CI **packaged build bundles a `case-box-contract` missing the LINK_* kinds** → the merged A3 link **create/unlink/relink IPC fails at runtime** (including the shipped renderer UI from PR #144). Unit tests miss it (they mock the DB).
- `WI-A3-LINK-D1-ROUNDTRIP-T1` cannot close D1 until clean builds reliably bundle the current contract.

The **source contract is correct**; the defect is the **committed-lock-vs-regenerated-tarball integrity drift**, structural to "gitignored tarball + committed integrity-pinned lock + non-reproducible pack."

## 3. Options

### Option 1 — commit the internal tarballs (un-gitignore + pin tracked bytes) — RECOMMENDED
Un-ignore `dist-tarballs/*.tgz` (+ `manifest.json`), commit the current tarballs (regenerated from current source), and commit the matching `package-lock.json`. The lock then pins **tracked bytes**, so `npm ci` is reproducible on every clone and the packaged build is deterministic.
- **Pros.** Simplest, fully reproducible, `npm ci` works, clean/CI packaged builds deterministic, preserves the decided Option-2 tarball-install architecture, directly unblocks D1. Drift is **visible in git** (a tarball change is a reviewable diff) and guardable.
- **Cons.** ~320 KB of binary `.tgz` in git; every contract/persistence source change requires a repack + recommit of the tarballs + lock. Mitigation: a **drift guard** (CI/gate) that re-packs the current source content and fails if the committed tarball's *content* (audit kinds etc.) is stale — so a forgotten repack is caught, not shipped.

### Option 2 — make `npm pack` byte-reproducible + refresh the lock
Normalize the staged tree (fixed mtimes via `SOURCE_DATE_EPOCH`/touch, stable tar ordering, gzip `-n`) so repack yields a stable hash; keep tarballs gitignored; commit a lock whose integrity matches the reproducible hash.
- **Pros.** No binaries in git; lock integrity stays stable across clones.
- **Cons.** Reproducible `npm pack` is genuinely fragile (gzip OS byte, tar uid/gid/ordering, npm/node version drift); high proof burden + a reproducibility CI check; one toolchain bump can silently break it and resurrect this exact bug. Higher complexity for a single-maintainer local-first tool. **It also does NOT preserve a plain fresh-clone `npm ci`:** because the tarballs are gitignored, a fresh clone has no `.tgz` files until a pre-`npm ci` generation step (`pack:internal`) runs — so `npm ci` is never a standalone first step, unlike Option 1 (committed tarballs).

### Option 3 — npm workspaces (drop file:-tarballs)
Restructure the repo so the desktop consumes the internal packages via npm workspaces (symlinked source); no tarballs/integrity.
- **Pros.** No tarballs, no integrity drift; clean installs resolve current source.
- **Cons.** **Reopens the settled Option-2 decision** (`plan-desktop-package-architecture-00.md` rev-3 chose tarball-install precisely to get a clean, electron-builder-packageable dependency closure; workspaces + electron-builder asar packaging of workspace deps was the problem tarball-install solved). Largest restructuring + re-validation of the packaged-build path. Disproportionate to the immediate defect.

### Option 4 — drop integrity-pinning for the file: deps
Configure npm to omit integrity for the internal `file:` deps.
- **Pros.** No EINTEGRITY failures.
- **Cons.** npm does not cleanly support per-dep integrity omission; it auto-pins in the lock. Achieving it means weakening/removing the lock or `.npmrc` hacks — weaker supply-chain semantics, npm-version-dependent, fragile. Does not make `node_modules` content reliably current (the silent-stale-install failure persists).

### Option 5 — status quo (rejected)
Proven broken: clean builds bundle a stale contract, the A3 link IPC fails at runtime, and D1 cannot close. Reject.

## 4. Comparison

| | Reproducible clean build | Binaries in git | Reopens Option-2 arch | Complexity / proof burden | Unblocks D1 |
|---|---|---|---|---|---|
| **1 commit tarballs** (rec.) | **Yes** | Yes (~320 KB) | No | Low (+ a drift guard) | Yes |
| **2 reproducible pack** | Yes *if* pack stays stable | No | No | High (fragile reproducibility) | Yes (if it holds) |
| **3 workspaces** | Yes | No | **Yes** | High (restructure + repackage) | Yes (eventually) |
| **4 no integrity pin** | No (stale installs persist) | No | No | Medium (npm-fragile) | No (unreliable) |
| **5 status quo** | No | — | — | — | No |

## 5. Decision

**Adopt Option 1 — commit the internal tarballs** (+ the matching `package-lock.json`), with a **semantic-payload drift guard** (§6 — a normalized payload comparison of both internal packages, not merely a LINK-kind grep). It is the lowest-risk, fully-reproducible fix that preserves the decided tarball-install architecture and directly unblocks D1; the binary-in-git cost is small and the drift risk is mitigated by a gate. **Option 2 (reproducible pack) is noted as a viable future hardening** if binaries-in-git later proves objectionable; **Option 3/4/5 are rejected** (reopen settled architecture / npm-fragile / proven broken).

## 6. Next implementation WI

**WI-A3-INTERNAL-DEPS-COMMIT-TARBALLS-00** (`Type: ASSET`/packaging; cc-suite-reviewed):
- **Scope.** (a) `npm run bootstrap` to regenerate `dist-tarballs/{case-box-contract,case-box-persistence}-0.1.0.tgz` + `manifest.json` from current source; (b) remove `dist-tarballs/` from `apps/lawbar-desktop/.gitignore` (un-ignore the `.tgz` + `manifest.json`); (c) commit the regenerated tarballs + `manifest.json` + the refreshed `apps/lawbar-desktop/package-lock.json` (now pinning the committed tarball bytes); (d) add a **semantic-payload drift guard** `scripts/workflow/check-internal-tarballs.sh` (or a desktop test), wired as a gate (see below).
- **Drift guard (semantic payload comparison, not a LINK grep).** The guard MUST catch general tarball↔source drift, not just this `LINK_*` case (a stale persistence tarball, stale generated schema, stale fixture, or any stale export must also fail). It re-stages BOTH internal packages from source into temp dirs the same way `pack:internal` does (apply the staged-manifest rewrites: `case-box-persistence`'s dep on `case-box-contract` → `"0.1.0"`, no residual `file:`/`link:`/`git+`/`portal:` specs), extracts the COMMITTED tarballs, and compares **normalized payload file hashes** of the extracted package contents (incl. the staged `package.json`) — **ignoring** tar/gzip metadata, file mtimes, and the manifest's `packedAt`. Any payload difference FAILS the gate. Retain a `LINK_*`-kinds smoke as an additional fast assertion (good D1 fail-fast), but it is not the guard's substance.
- **Expected allowed files.** `apps/lawbar-desktop/.gitignore`, `apps/lawbar-desktop/dist-tarballs/{case-box-contract-0.1.0.tgz,case-box-persistence-0.1.0.tgz,manifest.json}`, `apps/lawbar-desktop/package-lock.json`, the new guard script (+ its gate wiring), `dev-memo/deferred-audit-findings.md` (flip the packaging defect to closed), governance. **No** `src/**`/`electron/**`/`renderer/**`/`tests/**` product change; **no** source contract/persistence/schema change; **no** `package.json` change beyond what `npm install` legitimately requires (restore cosmetic churn).
- **Verification (clean-build acceptance).** From a clean checkout: `rm -rf apps/lawbar-desktop/node_modules && npm --prefix apps/lawbar-desktop ci` succeeds (lock matches committed tarballs — no EINTEGRITY); the desktop-resolved `node_modules/case-box-contract/dist/audit-log.js` shows all 3 LINK_* kinds (fail-fast smoke); the resolved `node_modules/case-box-persistence` is the freshly-intended payload AND its installed `package.json` depends on `case-box-contract: "0.1.0"` with NO residual `file:`/`link:` specs (proving the staged-rewrite tarball, not a source-relative install); `npm --prefix apps/lawbar-desktop run dist` succeeds and the packaged `release/*/lawbar.app` asar-bundled contract contains the kinds (extract-and-grep); the semantic drift guard passes; `npm --prefix apps/lawbar-desktop test` GREEN; `check-contract-integrity` clean. No stale local `node_modules` can mask the result because `npm ci` removes + re-extracts from the committed, integrity-matched tarballs.
- **A0.7.** Not expected (no geometry/marker/renderer/source code; it commits dependency artifacts) — confirm at that WI's review-plan.

## 7. How this unblocks D1

After WI-A3-INTERNAL-DEPS-COMMIT-TARBALLS-00, a clean `npm ci` + `npm run dist` produces a packaged app whose bundled `case-box-contract` contains the LINK_* audit kinds. `WI-A3-LINK-D1-ROUNDTRIP-T1` (env-gated seed hook + real-db round-trip, already review-validated) can then run `createLink` → resolver `valid` → clean export and **close D1**. The D1 lane should add a pre-flight assertion that the resolved/bundled contract contains the LINK_* kinds (failing fast if the env is stale) so it never silently re-hits this.
