TypeScript ESM project with NodeNext module resolution, Node ≥20 (contract package requires ≥22 for JSON import attributes), and node:test as the test runner. No bundler, no dual ESM/CJS build. Avoid suggesting Jest/Mocha/Vitest, webpack/rollup, CommonJS, or ts-node — they are out-of-band for this codebase.

Architecture is multi-package without a workspace runner: docs/contracts/ is the contract hub (schemas + validators + state machine + queue transport types); services/ocr-{worker,persistence,ingestion,review}/ are siblings depending on each other via file: paths. Treat docs/contracts/ as if it were packages/ocr-contract.

Boundaries that must hold:
- persistence is source of truth; queue is transport
- ocr-persistence MUST NOT runtime-depend on ocr-worker/ocr-worker-adapter (runtime cycle)
- queue transport types live in ocr-worker-contract; both InMemoryOcrQueue and SqliteOcrQueue implement OcrJobQueueBackend from the contract
- generated TypeScript under docs/contracts/src/generated/ is auto-derived from JSON schemas; treat as throwaway
- runtime validators in src/validate*.ts are authoritative; cross-schema invariants are runtime-only
- OcrQueueError codes are stable: dedupe_conflict, unknown_receipt, stale_receipt, lease_expired, invalid_claim — never collapse
- coordinator owns lifecycle, adapter must not

Step-staging conventions: ADRs under docs/adr/ pin decisions before code. Steps follow the 10x cadence (10C, 10E, 10F, 10G, 10H, 10H-A, 10I-B1, 10I-B2, 10J, 10K, 10L, 11F, 11G). Do not propose changes that 10H/10H-A defers to 10K (atomic createOcrJob+enqueue, withTransaction seam, queue→ocr_jobs FK, ingest.ts migration) unless reviewing 10K specifically.

Test discipline: prefer file-backed temp DBs (node:fs.mkdtemp) over `:memory:` for any SQLite test that depends on cross-connection visibility, WAL behavior, or busy_timeout — `:memory:` gives each connection a private schema (per ADR 10H-A §9).

Repo style is terse: one-line comments only when the WHY is non-obvious. No multi-paragraph docstrings, no trailing-summary comments in fixes.
