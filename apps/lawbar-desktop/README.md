# lawbar-desktop

First UI shell — Electron-based Mac client for the lawbar product.

**Status**: Token-compliance fixture only. NOT product UI. NOT signed. NOT notarized. NOT for distribution beyond the developer's own machine.

## What this is

A minimal Electron application that proves:
1. The Electron substrate ratified at commit `35cd9b6` works on macOS.
2. The night-mode theme foundation (`dev-memo/plan-night-mode-foundation-00.md`) renders 12 semantic tokens in both Light and Dark palettes.
3. System / Light / Dark mode switching responds to user input AND to live macOS appearance changes.
4. Theme preference persists across app launches via `app.getPath("userData")` with `productName: "lawbar"` (path: `~/Library/Application Support/lawbar/theme-preference.json`).

## What this is NOT

- A product feature. The renderer is a 12-panel theme token fixture, NOT lawyer-facing case-box UI.
- A renderer-side case-box integration. There is NO IPC channel exposing case-box-persistence to the renderer; no contextBridge surface for cases / matters / documents.
- A signed or notarized `.app`.
- Suitable for distribution beyond the developer's own machine.

### What this DOES carry (post-tarball-PoC)

Per `dev-memo/plan-desktop-pkg-arch-tarball-poc-01.md`, the packaged `.app` includes `case-box-contract` and `case-box-persistence` (with `better-sqlite3` native binding) as runtime dependencies. This proves the package architecture; it does NOT expose those packages to the renderer or to any product code path. The dependencies are reachable ONLY from the env-gated `globalThis.__lawbarTarballPocProbe` test hook (gated by `LAWBAR_TARBALL_POC_TEST_HOOK=true`); production launches never load them.

See `dev-memo/plan-first-ui-shell-00.md` (commit `f74b2b2` on `origin/main`) for the authoring plan.

## Dev workflow

### Fresh-clone bootstrap (REQUIRED before `npm install`)

Per `dev-memo/plan-desktop-pkg-arch-tarball-poc-01.md` §5.2, this package depends on two internal packages (`case-box-contract`, `case-box-persistence`) via `file:dist-tarballs/*.tgz` tarballs. **The tarballs are committed to git, not gitignored** — `dist-tarballs/*.tgz` and `manifest.json` are all tracked. They are regenerated by the `bootstrap` script, which must be run deliberately: nothing rebuilds them for you, so a change to `case-box-contract` source is invisible to this package until `bootstrap` (specifically its `pack:internal` + `refresh:internal-tarballs` steps) has been run. See `.claude/skills/contract-change-rebuild/SKILL.md`.

On a fresh clone (or after deleting `node_modules/` + `dist-tarballs/`):

```sh
cd apps/lawbar-desktop
npm run bootstrap     # builds case-box-* + packs tarballs + npm install (fail-fast `&&` chain)
```

The `bootstrap` script:
1. `npm --prefix ../../docs/contracts/case-box-contract run build` — builds case-box-contract.
2. `npm --prefix ../../services/case-box-persistence run build` — builds case-box-persistence.
3. `npm run pack:internal` — stages + rewrites manifest + packs both packages to `dist-tarballs/`.
4. `npm install` — resolves the now-existing tarball deps + runs `electron-builder install-app-deps` postinstall.

The chain is `&&`-joined, so any subcommand failure aborts immediately and propagates a non-zero exit out of `npm run bootstrap`.

### Regular workflow (post-bootstrap)

```sh
npm test                # main-process unit tests + Playwright Electron dev smoke
npm run dev             # build + launch Electron
npm run dist            # build a dev-only .app under dist/mac-arm64/ (UNSIGNED)
npm run test:packaged   # launch the packaged .app under the fail-closed wrapper (WI-2)
npm run test:tarball-poc # run the tarball PoC test (requires `npm run dist` to have run)
```

Requires Node 22.x or 24.x (per `engines.node`). Electron downloads a Chromium binary on first `npm install` (~120MB).
