## Work Items

### WI-1: Hermetic script-runner harness (stub PATH + clean env)
- **Description**: A shared helper (`apps/lawbar-desktop/tests/_release-script-harness.mjs`, `_`-prefixed so it is not collected) that runs either script under a fully controlled environment. Mechanism: `spawnSync("bash", [SCRIPT, ...args], { encoding: "utf8", cwd, env })` where `env` is **built from scratch**, never spread from `process.env`. It contains only `PATH` (temp stub dir first, then `/usr/bin:/bin:/usr/sbin`), `HOME` at a temp dir, and the case's explicit `APPLE_*` / `CSC_*` variables. The stub dir is created per-test with `mkdtempSync` and holds executable shell stubs for `security`, `codesign`, `spctl`, `xcrun`, `stapler`. Each stub is generated from a per-case `{ stdout, stderr, exitCode }` spec and appends its name and argv to an invocation-log file so tests verify by side effect, not inference.
- **Why the house pattern must not be copied**: `tests/backup-local-data.test.mjs` uses `env: { ...process.env, ...env }`. Reusing that here is a defect — `release-preflight.sh` reads exactly the variables a maintainer's release shell is likely to have set, so inheriting would make results depend on whether the developer has `APPLE_TEAM_ID` or `CSC_LINK` exported. Non-deterministic, and a secret-hygiene hazard.
- **Acceptance criteria**:
  - [ ] Harness spawns bash with an env object having no prototype chain to `process.env`; a control variable set only in the parent proves non-inheritance.
  - [ ] Stub dir is first on `PATH`, and `PATH` still resolves `grep` and `sed` (`/usr/bin`) — both scripts depend on them.
  - [ ] `/usr/sbin` is on `PATH` because `spctl` lives there, not in `/usr/bin`.
  - [ ] Every stub records invocations to a log file; the harness exposes the parsed log.
  - [ ] Each stub's exit code, stdout and stderr are independently configurable per case.
  - [ ] Temp dirs removed on teardown; no test writes inside the repo tree.
  - [ ] No credential, certificate or network access required.
- **Required tests**:
  - Harness runs a trivial probe script, returns exit code/stdout/stderr verbatim — Level 1.
  - A variable exported in the parent is absent inside the spawned script — Level 1.
  - Configured stub exit code and stdout reproduced exactly — Level 1.
  - Invocation log records stub name and full argv — Level 2 (side-effect on a real file).

### WI-2: Prove the stubs actually shadow the real system binaries
- **Description**: The highest-risk failure mode in the plan. All five binaries exist on any macOS host (`/usr/bin/security`, `/usr/bin/codesign`, `/usr/sbin/spctl`, `/usr/bin/xcrun`, `/usr/bin/stapler`). If a stub fails to shadow, preflight tests silently read the maintainer's real keychain and become machine-dependent. This WI makes that loud instead of silent. **Implement before anything that depends on the harness.**
- **Acceptance criteria**:
  - [ ] For each of the five binaries, a test proves the stub — not the system binary — ran, via the invocation log.
  - [ ] A test asserts the real `security` was not consulted, by having the stub emit a sentinel no real output could contain and asserting the script took the stub-driven branch.
  - [ ] The "keychain has no Developer ID identity" case is produced by a **stub emitting a no-identity fixture**, never by omitting the stub — omission would let `/usr/bin/security` run.
  - [ ] A guard test fails with a clear message if `PATH` construction ever lets a system binary resolve ahead of a stub.
- **Required tests**:
  - `security` stub invoked with `find-identity -v -p codesigning`, real binary not — Level 2.
  - `codesign`, `spctl`, `xcrun` stubs each invoked when `verify-macos-signing.sh` runs — Level 2.
  - With a no-identity stub, preflight reports the missing-identity branch regardless of host keychain — Level 1.

### WI-3: `release-preflight.sh` — signing-identity axis characterisation
- **Description**: Pin the three-branch signing check at lines 13–23, including branch ordering.
- **Acceptance criteria**:
  - [ ] Keychain identity present → passes, `[ok] Developer ID Application identity found in the keychain.`
  - [ ] No keychain + `CSC_LINK` non-empty + `CSC_KEY_PASSWORD` non-empty → passes.
  - [ ] No keychain + `CSC_LINK` non-empty + password unset/empty → `[MISSING] CSC_KEY_PASSWORD`, `fail=1`.
  - [ ] No keychain + `CSC_LINK` unset → missing-identity line plus the guidance `note`, `fail=1`.
  - [ ] `CSC_LINK=""` behaves identically to unset — a realistic CI misconfiguration.
  - [ ] **Short-circuit pinned**: keychain identity present means `CSC_KEY_PASSWORD` is never checked. Recorded as current behaviour; flagged in WI-11.
  - [ ] The `if` tests `grep`'s exit status, not `security`'s: a `security` stub exiting 127 with empty stdout falls through to the `elif`.
  - [ ] `grep -q` matches anywhere in output — a fixture containing both `Developer ID Application` and `0 valid identities found` still passes. Flagged in WI-11.
  - [ ] The `CSC_LINK`-without-password case emits **both** an `[ok]` and a `[MISSING]` line — tests must assert on exit code and the specific `[MISSING]` line, never on "output contains `[ok]`".
- **Required tests**: keychain fixture → `[ok]`, no signing `[MISSING]` — Level 1 via Level 3 · `CSC_LINK` + password → CSC `[ok]` — Level 1 · `CSC_LINK` without password → exit 1 + that `[MISSING]` — Level 1 · `CSC_LINK=""` treated as unset — Level 1 · neither → missing-identity + `note` — Level 1 · `security` exit 127 ≡ no identity — Level 1 · keychain present suppresses the password check — Level 1.

### WI-5: `release-preflight.sh` — the fail-closed cross-product (flagship)
- **Description**: The most valuable property here: `dist:release` must be structurally incapable of producing an artifact when credentials are incomplete. Two halves, and both must be pinned or neither means anything. Half one is the npm wiring — `dist:release` chains with `&&`, so a non-zero preflight prevents `npm run build` and `electron-builder` from executing at all. Half two is exhaustive enumeration.
- **Enumeration design**: full cartesian product of the signing axis (keychain × `CSC_LINK` × `CSC_KEY_PASSWORD` = 8) and the notarization axis (`APPLE_TEAM_ID` × the 2⁵ subsets of the five method variables = 64) = **512 cells**. Each runs the real script and asserts exit code against an oracle predicate written independently in the test file. Expected: exactly **55 pass, 457 fail** — verified arithmetically before this plan was persisted. Asserting those counts is the strongest single assertion in the suite; an off-by-one in the gate moves the count.
- **Cost**: ~512 bash spawns, roughly 8–12s, in its own file so it can be run alone. If measured runtime exceeds ~20s, reduce to one-axis-held-constant (69 cells) plus targeted interaction cases — **after measuring, not preemptively**.
- **Acceptance criteria**:
  - [ ] A test parses `package.json` and asserts `scripts["dist:release"]` begins with the preflight invocation and joins stages with `&&` — not `;`, not `||`. This is what converts "exit 1" into "no artifact".
  - [ ] The same test asserts `electron-builder` appears *after* preflight, so no reordering puts the build first.
  - [ ] All 512 cells executed; each exit code matches the oracle.
  - [ ] Passing cells asserted to be exactly 55, failing exactly 457.
  - [ ] Every failing cell exits with status 1 specifically and prints `release preflight FAILED`.
  - [ ] Every passing cell exits 0 and prints `release preflight OK`.
  - [ ] The oracle is an independent restatement of the two rules, never shelling out to the script under test.
  - [ ] Failure output names the exact cell so a regression is diagnosable without re-deriving the combination.
- **Required tests**: `dist:release` `&&`-chained, preflight first, builder last — Level 1 on parsed JSON · 512-cell enumeration vs oracle — Level 1 via Level 3 · aggregate counts 55/457 — Level 1 · failing cells emit the FAILED banner and the `dev-memo/desktop-macos-signing-notarization.md §4` pointer — Level 1.

### WI-11: Findings register — behaviour that looks wrong (NO BEHAVIOUR CHANGE IN THIS PLAN)
- **Description**: Characterisation-first means these are pinned as-is above and recorded for a separate decision. **Documentation only — a findings section in the test headers and a `dev-memo` note. Changes no script.** Severity ordering is the planner's; the decision is the maintainer's.
- **Findings, most severe first**:
  1. **`verify-macos-signing.sh` always exits 0 after the path guard.** Lines 14–41 contain no `exit` — verified 2026-08-13, line 12 is the only one. `npm run verify:signing` returns success on an adhoc, unsigned, un-notarized bundle. Any use as a gate — `verify:signing && ship` — is silently vacuous. The script's *text* is honest; its *exit status* is not. The one finding to prioritise.
  2. **Whitespace-only credentials satisfy every presence check.** `APPLE_TEAM_ID=" "` passes `[ -n … ]`. Identical defect class to the one hardened in `e9ff43c` ("reject whitespace-only audited reason across all 6 guards") — the project has an established position.

The gate passes a state the builder may reject.
  4. **`grep -q "Developer ID Application"` is an unanchored substring match.** It does not check the valid-identity count, nor distinguish a valid identity from an expired or revoked one in the listing.
  5. **`verify-macos-signing.sh` guards with `-d` only.** Any directory passes as a "bundle", including an empty one.
  6. **Stapler branch tests the wrong binary**: `command -v stapler` gates a body invoking `xcrun stapler`.

  - [ ] No `.sh` file modified by this work item.

## Risks & Assumptions

- **PATH shadowing is the load-bearing assumption.** All five stubbed binaries exist on any macOS host. If shadowing breaks, preflight tests silently read the maintainer's real keychain and become machine-dependent. WI-2 exists solely to make that loud, and must be implemented first.
- **Never inherit `process.env`.** The repo's existing precedent (`backup-local-data.test.mjs`) spreads the parent env. Copying that idiom here is a defect: a maintainer with real `APPLE_*` exported would get different results than CI.
- **The 512-cell oracle restates the script's logic in JS.** Correct for characterisation — the oracle *is* the specification of today's behaviour — but it means the oracle cannot discover that today's logic is wrong. That job belongs to WI-11.
- **Runtime cost is real**: ~512 bash spawns, estimated 8–12s, unmeasured until implementation. If over ~20s, reduce per WI-5's documented fallback — measure first.
- **Unmet integration obligation, stated plainly.** policy-core rule 6 requires a real-path test per mocked boundary. WI-9 discharges it only for the *adhoc/failure* direction. The *success* direction — a genuinely signed, notarized, stapled bundle reporting `OK`/`accepted`/`validated` — cannot be tested under the no-credentials constraint. That path remains verified only by the maintainer manually at release time. A known gap, not an oversight.
- **`spctl` and `stapler` may touch the network** on unstapled bundles. Hence WI-9 is opt-in and outside the push gate. Wiring the flag into CI would violate the network constraint.
- **The relative default path** in `verify-macos-signing.sh` makes its no-argument behaviour cwd-dependent. Tests must set `cwd` explicitly or be non-deterministic.
- **WI-9 depends on a build artifact** not committed and removable by a clean. The skip guard must handle absence without failing.
- **Assumption**: `dev-memo/desktop-macos-signing-notarization.md §4` is the correct remediation pointer, since preflight prints it. Not verified; WI-5 pins the string as emitted, not the document's existence. (Note: that lane document was absorbed into `docs/product/product-plan.md` §5 on 2026-08-12 and the source deleted — the pointer is likely stale, which is itself a candidate finding.)
- **The `test` script is a hand-maintained file list.** Three test files are already unregistered. Any new file silently joins them unless WI-10 is done.

## Deferred / Out of Scope

- **Any change to either shell script.** All six WI-11 findings are recorded and pinned, not fixed. Fixing them is a separate, explicitly-authorised work item, and each fix will invalidate its characterisation test on purpose.
- **A meta-test asserting every `tests/*.test.mjs` is registered.** Valuable and cheap, but it would fail immediately on the pre-existing unregistered files. Adding it requires first deciding whether those should run.
- **Running a real `electron-builder` build**, signed or unsigned. Excluded by constraint.
- **Testing `electron-builder.signed.cjs`** — its config content, its notarize hook, and whether it actually consumes the variables preflight checks. Preflight verifying `CSC_LINK` while the builder ignores it would be a real gap, but auditing that config is a distinct work item.
- **The success path of `verify-macos-signing.sh`** against a genuinely signed and notarized bundle. Requires a real Developer ID certificate.
- **Coverage and mutation gates.** No coverage tooling exists, all four thresholds are 0, `requireMutation` is false. Shell scripts are outside JS instrumentation regardless.
- **`postdist:release`, `dist`, and the unsigned dev path.** Only the release-gated path is in scope.
- **The Swift A0.7 evidence-harness defects.** Explicitly rejected in favour of this work; unchanged by this plan.
- **Windows/Linux signing.** macOS-only project.
