## 1. Code findings

### C-1 · Medium · `scripts/verify-macos-signing.sh:113` (missing counterpart near `:64`)

**The verdict-2 message is unactionable, and in the case that matters most it is false.**

The authority check is the only one of four verdict inputs with **no per-section verdict line**.
`codesign verify:`, `spctl:` and `stapler:` each print one; `devid` prints nothing. When authority
is the *sole* failure the run prints three successes and then points at a failing section that does
not exist:

```
  codesign verify: OK
  spctl: accepted
  stapler: ticket stapled
VERDICT: signed but NOT release-ready (exit 2) — see the failing section above.
```

That is exactly T8.20's scenario — the case written to pin the authority check — and T8.20 asserts
on that line without noticing it names nothing. For a tool whose product requirement is honest
reporting, a confident pointer to a nonexistent failure is worse than silence.

**Fix**: emit a fourth per-section line after `:64` (`authority: Developer ID` /
`authority: NOT Developer ID (…)`), reword `:113` to "see the failing check(s) above", extend T8.20.

### C-2 · Medium · `scripts/verify-macos-signing.sh:14, 58, 78, 105`

**The documented exit-1 "tooling error" is unreachable for `codesign` and `spctl`.**

Line 14 commits: `1  usage / bundle-path / tooling error — nothing was assessed`. Only the path
guard exits 1. The stapler probe handles absence correctly; `codesign` and `spctl` do not:

| scenario | actual exit | actual verdict |
|---|---|---|
| `codesign` missing | **3** | `UNSIGNED / adhoc dev build` |
| `spctl` missing | **2** | `signed but NOT release-ready` |
| `xcrun` missing | 2 | correct — `stapler: xcrun stapler unavailable` |

`2>&1` also folds the shell's own diagnostic into the report, indented like real evidence. A machine
without Command Line Tools is told its release build is an adhoc dev build. It never falsely reports
release-ready, which caps this at Medium.

**Fix**: capture `dv_rc`/`sp_rc`, route 127 to an exit-1 tooling error — or amend the header. The
header and the code must agree; the header is currently the untrue one.

### C-3 · Medium · `package.json` → `dist:release`

**Nothing in the repo ever runs the exit contract this work item exists to create.** `dist:release`
is `preflight && build && electron-builder`. Preflight is a *presence* check on credentials and
cannot observe the artifact. No ship path calls `verify:signing`. `forceCodeSigning: true` covers
the signing half loudly (hence Medium, not High); the **stapling half is unverified after build**.

Not a one-liner: `verify:signing` defaults to `release/mac-arm64/lawbar.app`, which is `npm run
dist`'s `target: dir` output, whereas `dist:release` emits dmg/zip. A fourth stage needs an explicit
path argument. See also T-3 — the current tests forbid adding the stage at all.

### C-4 · Low · `electron-builder.signed.cjs:17`

Finding 7 was fixed in the script only. The sibling release config still says
`See dev-memo/desktop-macos-signing-notarization.md.` — confirmed deleted. T4.9 asserts absence of
that string in the *script's stdout*, so the repo-level defect survives its own regression test.

### C-5 · Low · `scripts/verify-macos-signing.sh:33,36`

run assesses a bundle the caller did not name. Same class as the accepted last-wins behaviour, but
unlike last-wins it was not a deliberate decision.

## 2. Test-quality findings

### T-1 · Medium · `tests/verify-macos-signing.test.mjs:493-494`, helper at `:134-140`

**T8.19's third assertion is vacuous — it passes for every possible output.**

`sectionBetween` computes `b = ls.indexOf(to)` **without a start offset**. T8.19 passes `to = ""`, so
`b` resolves to the blank line at index 1 — before the `HDR_DV` anchor at index 2 — making the slice
`ls.slice(3, 1)` → always `[]`. Proven by rerunning T8.19's scenario with `codesign -dv` printing
loudly while still failing: the assertion still passed. The case's headline claim — "printing
**NOTHING**" — is not tested. Its other two assertions still carry the regression, so finding 8
remains pinned; only the "prints nothing" half is fiction.

**Fix**: `const b = to === null ? ls.length : ls.indexOf(to, a + 1);`

it by name. That is the very "looks like coverage while providing none" state T10.1/T10.2 exist to
prevent. The *exclusion* is correct (network); the *unrunnability* is not.

**Fix**: add a lane with an empty `gateOn` so it can be run deliberately.

## 4. Residual risk

**Verified rather than assumed.** The most load-bearing stub assumption is that
`codesign -dv --verbose=2` emits `Authority=` lines — if it did not, `devid` would always be 0, exit
0 would be unreachable on every real Developer-ID bundle, and no stubbed test could detect it because
every stub feeds Authority lines. Checked offline against `/System/Applications/Calculator.app`:
three `Authority=` lines present.

Three machine-dependence hypotheses were killed: `set -u` + `"$@"` with zero positional parameters is
**safe** on `/bin/bash 3.2.57`; `present()` strips the full `[[:space:]]` class (tab, NL, VT, FF, CR
and mixtures); and the anchored identity regex matches a CJK organisation name identically under
`LC_ALL=C`, `en_US.UTF-8` and `zh_CN.UTF-8` — relevant because the child env supplies no `LANG` while
the maintainer's real shell does.

**Genuinely unverifiable.** The exit-0 direction has no real-tool test and cannot have one under the
standing constraints: it needs a Developer ID certificate and a live notarization ticket.
Specifically unproven against real tools are that `spctl -a -vv -t exec` exits 0 and
`xcrun stapler validate` exits 0 on a genuinely notarized bundle.

**Duplicated rule.** `electron-builder.signed.cjs` gates notarization on JS truthiness of
`APPLE_TEAM_ID`, so `" "` would enable it with a whitespace team id; preflight rejects `" "` first, so
the composed system is safe today. Two encodings of one rule, stricter one upstream — fine, but it
will drift.

**Not re-measured by the reviewer**: the 100% shell line coverage and 18/18 mutation kill rate, both
inherited. Seven additional hand mutants were spot-checked against the suite (drop `-d "$APP"`; drop
the `-*` case arm; `present` → `[ -n ]`; `elif` → `if`; `st_rc -eq 0` → `-ne 127`; drop the `dv_rc`
disjunct; revert the stapler probe) — all seven killed by existing cases.
