## 0. Corrections to the plan that this matrix applies

Three plan defects and one imprecision were found while designing — **four corrections in total** (C-1..C-4), matching the count in the Totals section. Each is corrected below and the correction is load-bearing: an implementer following the plan literally would produce an unreachable test (C-1), an always-failing test (C-2), an unregistered test file (C-3), and would design the stapler cases against a condition the script does not have (C-4).

**C-1 — WI-8's "neither stapler nor a working xcrun" branch is unreachable under WI-1's mandated `PATH`.**
WI-1 acceptance criteria require `PATH = <stubdir>:/usr/bin:/usr/sbin`. Verified on this host: `/usr/bin/stapler` exists (`-rwxr-xr-x root wheel 119024`). Under a prepend `PATH`, `command -v stapler` therefore **always** succeeds, so the `else` branch printing `  stapler: xcrun stapler unavailable` can never be entered, and the WI-8 acceptance criterion demanding it can never be met.
*Correction*: the harness builds an **isolated** `PATH` containing **only** the stub dir. `bash`, `grep`, and `sed` are provided as logging pass-through stubs that `exec` the real absolute binaries (`/bin/bash`, `/usr/bin/grep`, `/usr/bin/sed`). Absence of a stub then means "not found" **deterministically on any host**, which is what makes both stapler disjuncts and the both-false case independently constructible. The child is spawned as `spawnSync("/bin/bash", [SCRIPT, ...args], …)` with an absolute interpreter path so launching does not depend on the child `PATH` at all.

**C-2 — WI-10's "full lane run exits 0" acceptance criterion is unachievable.**
`config.json` documents the `desktop` lane as **KNOWN RED**: `tests/smoke.electron.test.mjs:21` is a permanent, deliberate failure. `npm --prefix apps/lawbar-desktop test` therefore exits non-zero by design. A test asserting exit 0 would fail on day one, and running `npm test` from inside `npm test` is re-entrant.
*Correction*: WI-10 is verified by registration membership (T10.1/T10.2) plus a real-filesystem existence check over every registered path (T10.3). The "count rises above 953" criterion is dropped as unverifiable-without-re-entrancy and recorded in **Deferred**.

**C-3 — the plan's file list has no home for the WI-1/WI-2 cases.**
`_release-script-harness.mjs` is `_`-prefixed and explicitly *not* collected, but WI-1 and WI-2 both specify required tests. Those tests need a registered file.
*Correction*: this matrix adds two registered files to the plan's list — `tests/release-script-harness.test.mjs` (WI-1, WI-2, T9.1) and `tests/release-script-registration.test.mjs` (WI-10). Both are appended to `scripts.test` under WI-10.

**C-4 — restatement of WI-8 / WI-11-finding-6 (the plan's wording is imprecise).**
The plan says "`command -v stapler` gates a body that runs `xcrun stapler`". Line 32 is a **disjunction**:

```bash
if command -v stapler >/dev/null 2>&1 || xcrun stapler --help >/dev/null 2>&1; then
```

The branch is entered if **either** a standalone `stapler` binary is resolvable **or** `xcrun stapler --help` succeeds, but the body unconditionally runs `xcrun stapler validate`. Because `||` short-circuits, when a standalone `stapler` exists the second disjunct is **never evaluated** — so the mismatch bites exactly when a standalone `stapler` resolves and `xcrun stapler` does not work: the script reports on a tool it never consulted. Cases T8.7 / T8.8 / T8.9 cover the two disjuncts and the both-false case independently, and each is distinguished by a **distinct invocation-log signature**, not by output text alone.

**`security find-identity -v -p codesigning` stdout fixtures** (each carries `SENTINEL-KEYCHAIN-ONLY-Z`, a marker that appears **only** in keychain output, so WI-6 can prove `grep -q` never lets keychain listing reach stdout):

- `IDENTITY_PRESENT`:
  `  1) FAKEHASHAAAA "Developer ID Application: SENTINEL-ORG (SENTINEL-KEYCHAIN-ONLY-Z)"` / `     1 valid identities found`
- `NO_IDENTITY`:
  `     0 valid identities found`
- `EXPIRED_UNANCHORED` (T3.8):
  `  1) FAKEHASHBBBB "Developer ID Application: SENTINEL-ORG (SENTINEL-KEYCHAIN-ONLY-Z)" (CSSMERR_TP_CERT_EXPIRED)` / `     0 valid identities found`

**Stub mechanics.** Each stub is a generated `#!/bin/bash` script that (1) appends its own name and then one line per `argv` element to `$LAWBAR_STUB_LOG`, terminated by a blank line; (2) replays its stdout and stderr sidecar files using only bash builtins (`while IFS= read -r line; do printf '%s\n' "$line"; done < "$0.stdout"`) — no `cat`, because no external binary except the pass-throughs is resolvable; (3) `exit`s its configured code. One `argv` element per line means arguments containing **spaces** round-trip correctly (needed by T7.8). `$LAWBAR_STUB_LOG` is a harness-injected variable, which lets one stub dir be shared across many cells while each cell keeps a private log — the optimisation that makes WI-5's 512 spawns affordable.

**Mock-boundary posture, stated once.** The five stubbed binaries — `security`, `codesign`, `spctl`, `xcrun`, `stapler` — are system boundaries under `policy-core` rule 4 (keychain access, Gatekeeper assessment, and Apple's notary service, which is network I/O). Everything else is real: real `bash`, the real unmodified scripts, real filesystem via `mkdtempSync`, real `grep`/`sed`, real `package.json`. Nothing in this repo's own source is mocked.

**The honest unmet obligation, stated once.** `policy-core` rule 6 requires a real-path test per mocked boundary. For **U2** it is discharged in the failure direction by T9.2–T9.4 (real tools, real adhoc bundle, no stubbing). For **U1** *no real-path test can exist*: exercising the real `security` branch requires a Developer ID identity in the maintainer's login keychain, and exercising the notary branches requires real Apple credentials — both forbidden by the standing constraints and by this repo's secret hygiene. Every U1 case below therefore names that impossibility rather than pointing at a test that does not exist. This is a finding, recorded in **Deferred**, not a preference.

## WI-1 — Hermetic script-runner harness

**Unit**: U3 · **File**: `tests/release-script-harness.test.mjs` · **Lane for all cases**: `unit`

### T1.1 — `runScript` returns the child's exit code, stdout and stderr verbatim and unmerged
- **Category**: success
- **Lane**: unit
- **Input**: probe script written to a temp dir: `printf 'OUT-LINE\n'; printf 'ERR-LINE\n' >&2; exit 3`
- **Expected output**: `{ status: 3, stdout: "OUT-LINE\n", stderr: "ERR-LINE\n" }`
- **Observable side effect**: none
- **Assertion strategy**: **Level 1** — `assert.equal(r.status, 3)`, `assert.equal(r.stdout, "OUT-LINE\n")`, `assert.equal(r.stderr, "ERR-LINE\n")`. Exact equality, not `includes`, so a harness that concatenates the two streams fails.
- **Mock boundary**: none — real `/bin/bash`, real temp file.
- **Paired integration test**: n/a
- **Refactor that would break this**: switching `spawnSync` to `stdio: "inherit"`, or adding `2>&1` merging, or dropping `encoding: "utf8"` so buffers come back as `Buffer`.
- **Wiring-only self-check**: **Fails the substitution.** A hardcoded `{status:3,…}` return would pass T1.1 alone but is killed by T1.4, which drives different exit codes and payloads through the same function.

### T1.2 — a variable exported in the parent is absent in the child, while an explicitly supplied one is present
- **Category**: guard
- **Lane**: unit
- **Input**: test sets `process.env.LAWBAR_HARNESS_CONTROL = "PARENT-LEAK-CANARY"` immediately before the call; harness is asked to supply `APPLE_TEAM_ID=SENTINEL-TEAMID-A`. Probe: `printf '%s|%s\n' "${LAWBAR_HARNESS_CONTROL:-ABSENT}" "${APPLE_TEAM_ID:-ABSENT}"`
- **Expected output**: stdout exactly `ABSENT|SENTINEL-TEAMID-A\n`
- **Observable side effect**: none
- **Assertion strategy**: **Level 1** — one `assert.equal` on the composite line. Both halves in one assertion is deliberate: a harness that passes nothing at all would satisfy the first half, and a harness that spreads `process.env` would satisfy the second; only a correct harness satisfies both.
- **Mock boundary**: none.
- **Paired integration test**: n/a
- **Refactor that would break this**: someone copying `tests/backup-local-data.test.mjs`'s `env: { ...process.env, ...env }` idiom into the harness — which is precisely the defect WI-1 exists to prevent.
- **Wiring-only self-check**: **Fails the substitution.** No constant return satisfies both halves under T1.4's varying inputs.

### T1.3 — the child's exported-variable set contains no name the harness did not supply
- **Category**: boundary
- **Lane**: unit
- **Input**: harness supplies exactly `{ PATH, HOME, LAWBAR_STUB_LOG, APPLE_TEAM_ID }`. Probe uses only builtins: `for n in $(compgen -e); do printf '%s\n' "$n"; done`
- **Expected output**: every printed name ∈ `{PATH, HOME, LAWBAR_STUB_LOG, APPLE_TEAM_ID, PWD, SHLVL, OLDPWD, _}` (the trailing four are bash's own, unavoidable and deterministic)
- **Observable side effect**: none
- **Assertion strategy**: **Level 1** — compute `unexpected = printed.filter(n => !allowed.has(n))` and `assert.deepEqual(unexpected, [])`; separately `assert` each supplied name is present. Asserting the *absence set* rather than exact equality keeps it robust to bash version differences while still catching leakage exactly.
- **Mock boundary**: none.
- **Paired integration test**: n/a
- **Refactor that would break this**: adding a "convenience" pass-through such as `TMPDIR`, `LANG`, or `USER` to the harness env builder — each of which reopens host-dependence by degrees.
- **Wiring-only self-check**: **Fails the substitution.** The assertion is computed from the child's own reported environment, not from the harness's inputs.

### T1.4 — stub `exitCode`, `stdout` and `stderr` are configured independently and reproduced byte-for-byte
- **Category**: success
- **Lane**: unit
- **Input**: three stub specs driven through the same call — `{exitCode:0, stdout:"S-ZERO\n", stderr:""}`, `{exitCode:1, stdout:"", stderr:"E-ONE\n"}`, `{exitCode:127, stdout:"", stderr:""}` — invoked by a probe that runs `security; printf 'rc=%s\n' "$?"`
- **Expected output**: per spec — `S-ZERO\nrc=0\n`, `rc=1\n` with stderr `E-ONE\n`, `rc=127\n`
- **Observable side effect**: stub files exist and are mode `0o755`
- **Assertion strategy**: **Level 1** on each of the three stdout/stderr/rc triples. The three-way parameterisation is what kills a hardcoded harness.
- **Mock boundary**: `security` stub — required because the real binary reads the maintainer's login keychain. **No real-path test can exist for U1** (see §2).
- **Paired integration test**: none possible — stated, not omitted.
- **Refactor that would break this**: a stub template that emits stdout via `echo` (which would append a newline the spec did not ask for) or that drops `chmod 0o755`.
- **Wiring-only self-check**: **Fails the substitution.** Three distinct triples through one code path.

### T1.5 — the invocation log records each stub's name and full argv in call order, preserving arguments containing spaces
- **Category**: state
- **Lane**: unit
- **Input**: probe runs `security find-identity -v -p codesigning` then `codesign --verify "/tmp/a b c.app"`
- **Expected output**: parsed log deep-equals `[ {name:"security", argv:["find-identity","-v","-p","codesigning"]}, {name:"codesign", argv:["--verify","/tmp/a b c.app"]} ]`

- **Assertion strategy**: **Level 2** — read the real file with `readFileSync`, parse, `assert.deepEqual` against the expected array. Order is asserted, so a `Set`-based implementation fails.
- **Mock boundary**: `security` and `codesign` stubs (keychain / code-signing boundary). **No real-path test can exist for U1.**
- **Paired integration test**: none possible for U1; for `codesign` the real path is T9.2.
- **Refactor that would break this**: changing the stub's logging from one-arg-per-line to `"$*"`, which silently collapses `/tmp/a b c.app` into three arguments — the exact bug T7.8 depends on being absent.
- **Wiring-only self-check**: **Fails the substitution.** The assertion reads a real file written by a real child process.

### T2.1 — under the child `PATH`, all five binaries resolve inside the stub dir
- **Category**: guard
- **Lane**: unit
- **Input**: stub dir with all five stubs; probe `for n in security codesign spctl xcrun stapler; do printf '%s\n' "$(command -v "$n")"; done`
- **Expected output**: five lines, each `=== <stubDir>/<name>`
- **Observable side effect**: none
- **Assertion strategy**: **Level 1** — `assert.deepEqual(lines, names.map(n => join(stubDir, n)))`. Resolution is performed **by the child's own shell**, not recomputed in JS, so it measures the real thing.
- **Mock boundary**: the five stubs themselves are the subject; nothing else mocked.
- **Paired integration test**: none needed — the property under test is the harness's, not a boundary's.
- **Refactor that would break this**: appending `:/usr/bin:/usr/sbin` to the child `PATH` — which is exactly what the plan's WI-1 text asks for and what C-1 rejects. On this host that flips `stapler` (and only `stapler`, when its stub is deliberately omitted) to `/usr/bin/stapler`.
- **Wiring-only self-check**: **Fails the substitution.** The resolved paths come from the child process.

### T2.3 — `assertStubsShadow` throws, naming the binary, when a required stub is missing and not allow-listed

### T2.5 — `codesign`, `spctl` and `xcrun` stubs are each reached on a `verify-macos-signing.sh` run

- **Mock boundary**: `security` stub only. **Two stub dirs are created once for the whole file** (identity-present, no-identity) and reused across all 512 cells; only the env varies. This is what keeps the run affordable, and it is safe because the per-cell log path is injected via `$LAWBAR_STUB_LOG`.
- **Paired integration test**: none possible for U1.
- **Refactor that would break this**: **any** change to the two credential rules — that is the point. Note the oracle is a restatement of today's logic, so it cannot discover that today's logic is *wrong*; that job belongs to WI-11.
- **Wiring-only self-check**: **Fails the substitution.** The oracle is written independently in JS and never shells out to the script; 512 comparisons cannot be satisfied by a constant.

### T5.5 — the pass/fail split is exactly 55 / 457
- **Category**: determinism · **Lane**: unit
- **Input**: the T5.4 sweep results
- **Expected output**: `{ passed: 55, failed: 457, total: 512 }`
- **Assertion strategy**: **Level 1** — `assert.deepEqual(counts, {passed:55, failed:457, total:512})`. - **Mock boundary**: as T5.4.
- **Refactor that would break this**: relaxing the API-key conjunction from three variables to two moves `passed` to 5 × (8 + 8 − 2) = 70.
- **Wiring-only self-check**: **Fails the substitution.** An aggregate over 512 real process exits.

### T5.6 — every failing cell exits with status **1** specifically and prints the FAILED banner
- **Category**: failure · **Lane**: unit
- **Input**: the 457 failing cells
- **Expected output**: `status === 1` (not merely truthy) and stdout containing `release preflight FAILED — signing/notarization credentials are incomplete.`
- **Assertion strategy**: **Level 1** per cell — strict equality on the code, plus the banner. Strictness matters: `set -u` on an unbound variable would exit 127, and a signal-killed child yields `status === null`; "non-zero" would accept both, and neither means "the gate declined".
- **Mock boundary**: as T5.4. No real-path test possible for U1.
- **Refactor that would break this**: `exit 2` for a distinguishable failure class, or removing `set -u` such that a typo'd variable name silently reads as empty rather than aborting.
- **Wiring-only self-check**: **Fails the substitution.** T5.7 asserts the complementary property over the other 55 cells.

### T5.7 — every passing cell exits 0 and prints the OK banner
- **Category**: success · **Lane**: unit
- **Input**: the 55 passing cells
- **Expected output**: `status === 0` and stdout containing `release preflight OK — proceeding with the signed + notarized build.`; zero `[MISSING]` lines
- **Assertion strategy**: **Level 1** per cell on all three.
- **Mock boundary**: as T5.4.
- **Refactor that would break this**: adding a new mandatory credential (e.g. `APPLE_NOTARY_KEYCHAIN_PROFILE`), which would empty this set entirely.
- **Wiring-only self-check**: **Fails** — complementary to T5.6.

### T5.8 — the same cell run twice produces a byte-identical result
- **Category**: determinism · **Lane**: unit
- **Input**: one passing cell and one failing cell, each executed twice with freshly-created log paths
- **Expected output**: identical `status`, byte-identical `stdout`, byte-identical `stderr` across the two runs

- **Refactor that would break this**: adding a timestamp, hostname, or elapsed-time line to the preflight output.
- **Wiring-only self-check**: **Fails the substitution** in combination — a constant-returning harness would pass this case alone but is killed by T5.4.
- **Note on runtime**: the plan estimates 8–12s for 512 spawns and mandates measuring before reducing scope. The reduction fallback (69 cells) must **not** be applied preemptively. Runtime is reported by the test reporter and deliberately **not asserted** — a wall-clock assertion is the classic flaky test, and its failure mode (a slow CI box) is not the failure this suite is for.

## WI-6 — Secret non-disclosure property

**Unit**: U1 · **File**: `tests/release-preflight.test.mjs` · **Lane for all cases**: `unit`

Every case in WI-6 asserts non-disclosure **together with** a positive branch assertion in the same test. Alone, a non-disclosure assertion is vacuous — a script replaced by `echo OK; exit 0` would satisfy it. The pairing is mandatory, not stylistic.

---

### T6.1 — a passing run leaks no sentinel, and leaks no keychain listing
- **Category**: success · **Lane**: unit
- **Input**: all eight §2 sentinels set; `security` stub → `IDENTITY_PRESENT` (which contains `SENTINEL-KEYCHAIN-ONLY-Z`)
- **Expected output**: exit 0 and the OK banner **and** the keychain `[ok]` line — the positive half; and for each of the nine sentinel strings individually, absence from `stdout + stderr`
- **Observable side effect**: stdout, stderr
- **Assertion strategy**: **Level 1** — three positive assertions plus **nine separate** `assert.ok(!combined.includes(s), \`leaked ${name}\`)` calls, one per variable **by name**, so a single leaking variable is identified without bisection. `SENTINEL-KEYCHAIN-ONLY-Z` is the ninth and pins a distinct property: `grep -q` suppresses `security`'s output, so the keychain listing never reaches the terminal.
- **Mock boundary**: `security` — real invocation would place real keychain contents in the assertion's input, which is exactly what must never happen in a test. **No real-path test can exist for U1.**
- **Refactor that would break this**: adding a diagnostic such as `echo "[ok] using team $APPLE_TEAM_ID"`, or dropping `-q` from the `grep` so the identity listing is echoed.
- **Wiring-only self-check**: **Fails the substitution** *because of the pairing.* The negative assertions alone would survive `return "OK"`; the three positive assertions plus T6.2's opposite exit code do not.

### T6.2 — a failing run leaks no sentinel either
- **Category**: failure · **Lane**: unit
- **Input**: all eight sentinels set **except** the signing axis is starved — `security` stub → `NO_IDENTITY` and `CSC_LINK` unset while `CSC_KEY_PASSWORD` remains a sentinel (an unusual but realistic half-configuration)
- **Expected output**: exit 1 and the FAILED banner and the missing-identity line — the positive half; plus per-sentinel absence
- **Observable side effect**: stdout, stderr
- **Assertion strategy**: **Level 1** — three positive assertions plus per-name absence assertions. The failure path is where leakage is most likely, because error messages are where developers add "helpful" context.
- **Mock boundary**: `security`. No real-path test possible for U1.
- **Refactor that would break this**: an error message such as `[MISSING] CSC_KEY_PASSWORD for cert $CSC_LINK`.
- **Wiring-only self-check**: **Fails the substitution.** Positive assertions differ from T6.1's.

### T6.3 — no sentinel appears in the `security` invocation log
- **Category**: guard · **Lane**: unit
- **Input**: as T6.1
- **Expected output**: n/a (the observable is the log)
- **Observable side effect**: the invocation-log **file** contains one `security` record with `argv === ["find-identity","-v","-p","codesigning"]`
- **Assertion strategy**: **Level 2** — read the real log file back from disk and assert (a) `deepEqual` on the argv, and (b) for each of the eight credential sentinels, absence from the serialised log. Argv equality is the stronger of the two: it forbids *any* extra argument, not merely sentinel-shaped ones.
- **Mock boundary**: `security`. No real-path test possible for U1.
- **Refactor that would break this**: adding `-s "$CSC_LINK"` or passing a keychain path derived from a credential variable — which would put a secret on the process argument list, visible to `ps` for every user on the machine. That is the concrete harm this case exists to prevent.
- **Wiring-only self-check**: **Fails the substitution.** The assertion reads a file written by a real child; `deepEqual` on argv is Level 2 side-effect verification, not Level 6 mock-arg inspection — the log is a real artifact, not a mock's call record.

### T6.4 — `check-no-real-data.mjs` stays green on the new files
- **Category**: determinism · **Lane**: unit
- **Input**: `spawnSync("node", ["scripts/check-no-real-data.mjs", ...the six new file paths], { cwd: apps/lawbar-desktop })` — the scanner accepts a user-supplied path list, so this is targeted rather than a whole-corpus rerun
- **Expected output**: exit 0, empty match listing
- **Observable side effect**: none
- **Assertion strategy**: **Level 3** — the real scanner, on the real new files, through its real CLI. Not a re-implementation of its regexes.
- **Mock boundary**: none — real child process running real project tooling.
- **Paired integration test**: n/a (this **is** the real path).
- **Refactor that would break this**: someone "making the fixtures more realistic" by giving `APPLE_ID` an email shape, `CSC_KEY_PASSWORD` an `xxxx-xxxx-xxxx-xxxx` shape, or the identity fixture a plausible team-id digit string. Each would trip a specific scanner pattern (`email`, `phone-us`, `id-cn`), which is precisely why the §2 sentinels are letter-suffixed with no digit runs.
- **Wiring-only self-check**: **Fails the substitution.** Runs real tooling against real files; a green result is produced by the scanner, not by the test.

- **Assertion strategy**: **Level 2** on the log signature — `assert.deepEqual(log.filter(r=>r.name==="xcrun").map(r=>r.argv), [["stapler","validate",appPath]])` and `assert.equal(log.filter(r=>r.name==="stapler").length, 0)` — **plus Level 1** on the two output assertions. - **Mock boundary**: `stapler`, `xcrun` (notary-ticket lookup — network). **Paired integration test**: T9.4 exercises the real branch on the real host, where both disjuncts happen to be true; the *divergent* configuration this case constructs cannot be produced on a real host without removing `/usr/bin/stapler`, and that is stated rather than hidden.
- **Refactor that would break this**: the finding-6 fix — either `command -v xcrun` in the condition, or a body that prefers the standalone `stapler` when it exists. This test is designed to fail then.
- **Characterisation marker**: required — *"pins WI-11 finding 6. The condition and the body test different binaries."*
- **Wiring-only self-check**: **Fails the substitution.** The zero-`stapler`/one-`xcrun` signature is unique to this branch and distinguishes it from T8.8 and T8.9, which produce different signatures.

### T8.8 — stapler disjunct **B**: no standalone `stapler`, `xcrun stapler --help` succeeds → the branch is entered via the second disjunct
- **Category**: failure · **Lane**: unit
- **Input**: `stapler` stub **absent** (harness called with `allowMissing: ["stapler"]`, per T2.7); `xcrun` stub exits 0 for `--help` and **1** for `validate`
- **Expected output**: exit 0; stdout contains `  stapler: no ticket stapled (expected for unsigned / un-notarized builds)`
- **Observable side effect**: **log signature** — exactly **two** `xcrun` records, in order `["stapler","--help"]` then `["stapler","validate","<appPath>"]`; zero `stapler` records
- **Assertion strategy**: **Level 2** on the two-record ordered signature, **plus Level 1** on the output line. The record **count** is the discriminator against T8.7 (one record) and T8.9 (one record with different argv). Output text alone cannot tell T8.7 from T8.8 — they print the identical line.
- **Mock boundary**: `xcrun`. **Paired integration test**: T9.4.
- **Refactor that would break this**: reordering the disjuncts to `xcrun stapler --help || command -v stapler`, which would change T8.7's signature to two records and T8.8's to two — collapsing the distinction this pair exists to draw.
- **Characterisation marker**: required.
- **Wiring-only self-check**: **Fails the substitution.** Three cases print overlapping text and are separated only by real invocation signatures.

### T8.9 — both disjuncts false → `stapler: xcrun stapler unavailable`
- **Category**: guard · **Lane**: unit
- **Input**: `stapler` stub **absent**; `xcrun` stub exits **1** for `--help`

- **Assertion strategy**: **Level 2** on the single-record signature (proving `validate` was never attempted), **plus Level 1** on presence and absence of the two output lines.
- **Mock boundary**: `xcrun`; `stapler` deliberately absent. **This case is unreachable under the plan's prescribed `PATH`** (`/usr/bin/stapler` exists on this host) and is what forces correction **C-1**. It has **no** real-path counterpart: a macOS host without `/usr/bin/stapler` is outside the project's supported configuration. Stated, not hidden.
- **Refactor that would break this**: dropping the `else` arm, or replacing the condition with an unconditional `xcrun stapler validate`.
- **Wiring-only self-check**: **Fails the substitution.** Unique log signature plus a unique output line.

### T8.10 — a successful `xcrun stapler validate` prints its output and suppresses the fallback

### T8.11 — both `Interpretation:` lines are printed on a fully-failing run
- **Category**: determinism · **Input**: the fully-failing configuration (see T8.12)

- **Wiring-only self-check**: **Fails the substitution.** Exact multi-line ordered equality on real output.

### T8.12 — **the critical characterisation**: a fully-failing run still exits **0** *(WI-11 finding 1, highest severity)*
- **Category**: failure · **Lane**: unit
- **Input**: `codesign -dv` exit 1 stdout `Signature=adhoc`; `codesign --verify` exit **1** stdout `code object is not signed at all`; `spctl` exit **3** stdout `rejected` + `source=no usable signature`; `stapler` present, `xcrun` exit **1** — i.e. an unsigned, un-notarized, Gatekeeper-rejected bundle, every check failing
- **Expected output**: **`status === 0`**
- **Observable side effect**: stdout simultaneously contains `Signature=adhoc`, `  codesign verify: FAILED (adhoc/unsigned builds fail deep-strict verify)`, `rejected`, and `  stapler: no ticket stapled (expected for unsigned / un-notarized builds)`
- **Assertion strategy**: **Level 1** — `assert.equal(r.status, 0)` **together with** the four failure-evidence assertions in the same test. The pairing is the whole point: exit 0 alone is unremarkable; exit 0 *while the output enumerates four failures* is the finding. `npm run verify:signing && ship` is therefore silently vacuous — the script's **text** is honest, its **exit status** is not.
- **Mock boundary**: all four binaries. **Paired integration test**: **T9.4**, which asserts the identical exit-0-despite-failure on the real adhoc bundle with the real tools — the strongest available confirmation that the stubbed characterisation is not an artifact of stubbing.
- **Refactor that would break this**: the finding-1 fix — adding `exit 1` when `cs_rc -ne 0`, or an aggregate `rc` accumulated across the three checks. **This test is designed to fail when that fix lands.**
- **Characterisation marker**: required, and the most emphatic in the suite — *"pins WI-11 finding 1 (highest severity). Exit 0 here is the DEFECT, not the contract. Do not read this test as an endorsement; delete it as part of the fix."*
- **Wiring-only self-check**: **Fails the substitution.** No constant satisfies exit 0 plus four specific output strings that the same run must have produced, and T7.1 asserts exit 1 from the same script.

### T8.13 — two identical runs produce byte-identical output and the same exit code

- **Mock boundary**: as T8.12. **Paired integration test**: T9.2–T9.4 (real tools; determinism there is not asserted, since real `spctl` may vary with network reachability — which is itself the reason WI-9 is opt-in).
- **Refactor that would break this**: adding an elapsed-time or date line to the report.
- **Wiring-only self-check**: **Fails the substitution** in combination — killed by T8.1 vs T8.2, which require different outputs.

## Deferred

Behaviours deliberately not covered, each with its reason. This section is non-empty on purpose.

1. **The success direction of `verify-macos-signing.sh`.** A genuinely signed, notarized, stapled bundle reporting `Authority=Developer ID Application: …` / `accepted` / `validated` cannot be tested: it requires a real Developer ID certificate and a real notarization ticket, both forbidden. T8.1 and T8.10 pin the success *reporting logic* with stubs; nothing verifies that the real tools produce those strings on a real signed bundle. **This is `policy-core` rule 6's obligation, unmet and stated.** That path stays verified only by the maintainer, manually, at release time.

2. **Any real-path test for `release-preflight.sh`.** Exercising the real `security` keychain branch or the real notarization branches requires a Developer ID identity in the login keychain and real Apple credentials. Every U1 case is therefore stub-bound with no integration counterpart. Under `policy-core` completion gate 5 this is a standing finding for U1, not a gap that further test design can close.

3. **The full `desktop` lane run asserting exit 0** (WI-10's dropped criterion). The lane is documented KNOWN RED — `tests/smoke.electron.test.mjs:21` is a deliberate permanent failure kept because it is the only test proving the app launches. Asserting exit 0 would fail on day one, and invoking `npm test` from inside `npm test` is re-entrant. Registration integrity is verified instead by T10.1–T10.3.

4. **No coverage or mutation gate.** `config.json` sets all four `coverageThresholds` to 0, every lane to `coverage: "none"`, and `requireMutation: false`, because no coverage tooling exists in any of the nine package manifests. Shell scripts are outside JS instrumentation regardless, so even adding `c8` would not measure the two units this matrix is actually about.

5. **`electron-builder.signed.cjs`.** Whether the builder actually consumes the variables preflight checks — in particular whether it prefers `CSC_LINK` over a keychain identity, which is the premise of WI-11 finding 3 — is unverified. Preflight validating a variable the builder ignores would be a real gap. Auditing that config is a distinct work item; T3.9 pins only preflight's silence, not the builder's preference.

6. **A real `electron-builder` run, signed or unsigned.** Excluded by constraint. T5.2/T5.3 substitute a marker-writing builtin for stages 1–2 while executing `stages[0]` verbatim from the manifest — conservative, but it does not prove the build stages themselves work.

7. **A meta-test asserting every `tests/*.test.mjs` is registered.** Cheap and valuable, but it would fail immediately on the three pre-existing unregistered files (`document-storage.unit.test.mjs`, `wrapper.test.mjs`, `smoke.packaged.electron.test.mjs`). Adding it requires first deciding whether those three should run — a decision this plan does not own. T10.3 covers the inverse direction (every registered path exists) because that one is green today.

8. **Wall-clock runtime assertions.** WI-5's cost is reported by the test reporter, never asserted. A timing assertion's failure mode is a slow machine, not a regression; T5.8 and T8.13 cover the property that actually matters (determinism) without the flakiness.

9. **T8.9's real-path counterpart.** "Neither a standalone `stapler` nor a working `xcrun`" cannot occur on a supported host — `/usr/bin/stapler` is present on macOS. The branch is reachable only under the isolated `PATH`, and that is stated in the case rather than papered over.

10. **`postdist:release`, `dist`, and the unsigned dev path.** Only the release-gated path is in scope.

11. **Windows/Linux signing, and the Swift A0.7 evidence-harness defects (D1 NaN bypass, D2 zero-sample pass).** Out of scope by project shape and by the plan's explicit target selection.
