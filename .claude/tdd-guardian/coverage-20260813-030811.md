## Why the configured audit did not run

`/tdd-guardian:audit-coverage` stops at Step 2 when no lane sets `coverage: "include"`.
Verified against `.claude/tdd-guardian/config.json` at this timestamp:

- all **10** lanes are `coverage: "none"`; none defines `coverageSummaryPath`
- all four `coverageThresholds` are **0**, `coverageMode: "absolute"`
- **0 of 10** package manifests carry `c8`, `nyc`, or `--experimental-test-coverage`

This is the documented decision from init, not drift. There is a second and stronger
reason it could not have helped here: **JS instrumentation cannot measure a bash script.**
Adding `c8` today would report zero lines for both files below.

## What was measured instead

Both scripts were copied and instrumented with `PS4='+COV:${LINENO}:'` + `set -x`, with
stderr redirected to a trace file (`BASH_XTRACEFD` is bash 4.1+; system bash is 3.2.57).
The full test suite was then run against the instrumented copies via `LAWBAR_SCRIPT_DIR`.

**All 93 registered tests still passed against the instrumented copies**, so the
instrumentation is behaviour-transparent and the trace reflects the real execution paths.
Trace records collected: **17127** (including the opt-in real-bundle suite).

## Two lines excluded from the denominator, with proof

Naive counting reports 96.7% and 98.4%. Both misses are `set -x` artifacts, not gaps:

| Line | Construct | Proof it executed |
|---|---|---|
| `release-preflight.sh:27` | `has_developer_id() {` — function-definition header | body at lines 28-29 ran **300** times |
| `verify-macos-signing.sh:28` | `-*)` — `case` pattern label | branch body at lines 29-31 ran **4** times |

bash emits no trace record for a function-definition header or a case pattern label. Counting
them as uncovered would understate coverage; excluding them without this evidence would
overstate it.

## Honest limits

1. **Line coverage is not behavioural adequacy.** The stronger evidence for these scripts is
   the two-sided run recorded in the addendum: 28 regression cases fail against the preserved
   pre-fix scripts and pass against the current ones.
2. **The release-ready success path is covered only with stubs.** No real Developer ID
   certificate exists, so `codesign`/`spctl`/`stapler` agreeing on a genuinely signed and
   notarized bundle is unverified against reality.
3. **This measurement is not wired into any gate.** It was produced on demand and is not
   re-run by `npm test` or CI. Treat the number as a snapshot at 20260813-030811.
4. **The JS side of this package remains unmeasured** — that is unchanged by this report and
   is a project-level decision, not an oversight of this work item.
