# Addendum — posture change from characterisation-first to regression-first

**Applies to**: `.claude/tdd-guardian/tests-20260813-013156.md` (the base matrix)
**Reason**: the maintainer directed "fix then implement". Both scripts were fixed on 2026-08-13 **before** any test was written. Every fix was proven by executing the scenario against a saved pre-fix copy and the post-fix script side by side.

The base matrix's **design** survives intact — the isolated-`PATH` harness (C-1), stub mechanics, the sentinel register, the cross-product method, the secret non-disclosure property, and the registration checks are all unchanged. What changes is the **expected outcome** of the cases that pinned defects, plus new cases for behaviour that did not previously exist.

**Posture now**: every case asserts CORRECT behaviour. A case that previously carried a *characterisation marker* becomes a **regression test** — it must fail against the pre-fix script and pass against the current one. That two-sided requirement replaces the old "wiring-only self-check" as the strongest available proof, and it is checkable: the pre-fix scripts are preserved for exactly this purpose.

## 1. What actually changed in the scripts

### `release-preflight.sh`

Two new helpers:

```bash
present() { [ -n "${1//[[:space:]]/}" ]; }   # bash 3.2-safe, verified on /bin/bash 3.2.57

has_developer_id() {
  security find-identity -v -p codesigning 2>/dev/null |
    grep -Eq '^[[:space:]]*[0-9]+\)[[:space:]]+[0-9A-Fa-f]+[[:space:]]+"Developer ID Application:[^"]*"[[:space:]]*$'
}
```

**Branch order is INVERTED.** `CSC_LINK` is now tested *first*, and wins when set:

```bash
if present "${CSC_LINK:-}"; then
  echo "[ok] CSC_LINK is set (electron-builder will sign from this certificate, not the keychain)."
  present "${CSC_KEY_PASSWORD:-}" || { echo "[MISSING] CSC_KEY_PASSWORD (password for the CSC_LINK cert)."; fail=1; }
elif has_developer_id; then
  echo "[ok] Developer ID Application identity found in the keychain."
else
  echo "[MISSING] no Developer ID Application identity in the keychain and CSC_LINK is unset."
  note "import the cert into the login keychain, OR set CSC_LINK + CSC_KEY_PASSWORD."
  fail=1
fi
```

The inversion is not cosmetic and is not a preference. `app-builder-lib/out/macPackager.js:26-29` builds a **temporary keychain from `CSC_LINK`** and never consults the login keychain; only when `CSC_LINK` is null (line 49) does it fall back to the default keychain. So "keychain identity present" cannot excuse a missing `CSC_KEY_PASSWORD` — that combination signs from `CSC_LINK` and fails at build time, *after* the gate has said OK.

All six notarization presence checks now route through `present`.

The failure-message pointer changed — the old target was deleted in `88c8c46`:

```
See docs/product/product-plan.md -> 'macOS Developer-ID signing + notarization' section 6.
Aborting the release build (the unsigned dev build is 'npm run dist').
```

### `verify-macos-signing.sh`

Rewritten around an **exit contract**. This is the headline change:

| Exit | Meaning |
|---|---|
| 0 | release-ready: Developer ID authority, deep-strict OK, Gatekeeper accepted, ticket stapled |
| 1 | usage / bundle-path / tooling error — nothing was assessed |
| 2 | assessed and signed, but NOT release-ready |
| 3 | assessed, and the bundle is unsigned or adhoc-signed (`npm run dist` default) |

`--report` suppresses verdicts 2 and 3 (exits 0 instead); a usage/path error still exits 1.

Other changes:
- **Argument parsing** added: `--report` anywhere; any other `-*` token is an error (`verify: unknown option: X` + usage, exit 1); a non-flag token is the bundle path. **Correction (2026-08-13, verified by execution):** an earlier draft of this addendum said "the *first* non-flag token". That is wrong. The loop is `for arg in "$@"` with `*) APP="$arg"`, so each non-flag token overwrites the previous and the **LAST one wins**. Accepted as-is rather than "fixed": passing two paths is a user error either way, and the run announces its subject on the first output line (`== bundle: $APP ==`), so the behaviour is self-declaring rather than silent. T12.5 pins last-wins.
- **Structural bundle guard**: `-d "$APP"` **and** `-f "$APP/Contents/Info.plist"` **and** `-d "$APP/Contents/MacOS"`. The `.app` suffix is deliberately **not** required — the name is a convention, the structure is the thing, and rejecting a validly-structured bundle for its name adds a failure mode without adding safety.
- **Capture-then-print** for every tool. `codesign -dv`, `spctl` and `xcrun stapler validate` previously piped straight into `sed`, which discards the tool's status and substitutes sed's (always 0). Proven: `false | sed 's/^/ /'` returns 0. Each tool's rc is now captured before any pipe, via `out="$(cmd 2>&1)"; rc=$?`, then printed through an `indent` helper.
- **Stapler probe matches the body**: `xcrun -f stapler` replaces `command -v stapler || xcrun stapler --help`. The old condition accepted a standalone `stapler` and then ran `xcrun stapler` regardless.
- New per-section verdict lines: `  spctl: accepted` / `  spctl: rejected`, `  stapler: ticket stapled` / `  stapler: no ticket stapled (…)` / `  stapler: xcrun stapler unavailable`.
- The two `Interpretation:` lines are **replaced** by one `VERDICT:` line.

Verdict logic:

```bash
if   [ "$dv_rc" -ne 0 ] || [ "$adhoc" -eq 1 ]; then verdict=3
elif [ "$devid" -eq 1 ] && [ "$cs_rc" -eq 0 ] && [ "$sp_rc" -eq 0 ] && [ "$st_rc" -eq 0 ]; then verdict=0
else verdict=2
fi
```

where `adhoc` is `^Signature=adhoc` in the `codesign -dv` output and `devid` is `^Authority=Developer ID Application:` in the same output. **`--verbose=2` does emit `Authority=` lines** — verified against an Apple-signed control bundle (3 lines). The adhoc bundle shows zero because an adhoc signature has no authority chain; that is correct, not a defect.

### `package.json`

`"verify:signing:report": "bash scripts/verify-macos-signing.sh --report"` added after `verify:signing`. Two named intents beat `npm run verify:signing -- --report`.

### WI-5 — the cross-product (numbers changed)

New oracle, stated independently of the script:

```js
const signOk   = (K, L, P) => (L ? P : K);                       // CSC_LINK wins when set
const notaryOk = (T,A,B,C,D,E) => T && ((A && B) || (C && D && E));
const pass     = (...c) => signOk(c[0],c[1],c[2]) && notaryOk(c[3],c[4],c[5],c[6],c[7],c[8]);
```

| | cells | pass | fail |
|---|---|---|---|
| pre-fix rule | 512 | 55 | 457 |
| **post-fix rule** | **512** | **44** | **468** |

- T5.4/T5.5: assert 512 cells against the new oracle; assert **exactly 44 pass / 468 fail**.
- T5.6/T5.7: unchanged in form — failing cells exit 1 and print `release preflight FAILED`; passing cells exit 0 and print `release preflight OK`.
- **T5.9 *(new)* — the differential assertion, and the strongest single test in the suite.** Evaluate both the pre-fix and post-fix oracles over all 512 cells and assert:
  - exactly **11** cells moved pass → fail;
  - exactly **0** cells moved fail → pass (a hardening fix may only tighten);
  - all 11 share the signing signature **`K=1, L=1, P=0`** — keychain identity present, `CSC_LINK` set, password missing.

  That last clause proves the fix is *precisely* scoped: it removes finding 3's configuration and nothing else. Any accidental widening or narrowing moves one of those three numbers.
- T5.1–T5.3 (the `dist:release` `&&`-chain) are unchanged.

## 3. Two-sided verification requirement (replaces the characterisation markers)

The pre-fix scripts are preserved at
`<scratchpad>/prefix-scripts/{release-preflight.sh,verify-macos-signing.sh}`
(sha256 `68ada7a7…` and `92c33624…`).

Every case listed above as **FLIPS** or **regression test** must be run against **both**. It passes review only if it **fails** against the pre-fix copy and **passes** against the current script. A regression test that passes against both is not testing the fix.

This is not optional colour: it is the only evidence that distinguishes a test that catches the defect from a test that merely agrees with the current code.
